# EIDOS 디자인 토큰

> **권장 기본값입니다.** 기법 예시와 생성 HTML은 이 토큰에서 출발해 색톤을 맞추되, 내용에 색이 더 필요하면 에이전트가 판단해서 늘리거나 바꿔도 됩니다.
> 목표는 "같은 톤으로 보이는 것"이지 "이 목록 밖의 색을 쓰지 않는 것"이 아닙니다.

## 기반 테마

- 출처: tweakcn **Claude +** (https://tweakcn.com/themes/cmdght103000n04lh3e2ae93r)
- 원본 형식: shadcn registry JSON (`https://tweakcn.com/r/themes/cmdght103000n04lh3e2ae93r`)
- 성격: 따뜻한 크림색 배경, 테라코타 주황 강조색, 라이트와 다크 모두 제공

### 그대로 가져온 것

배경, 글자, 카드, 테두리, 강조색(primary), 보라(chart-2), 그림자, 라운드 값.

### 시각화 용도로 고친 것

원본은 앱 UI용 테마라서, 다이어그램과 차트에 쓰기에는 아래 문제가 있었습니다. 대비율은 원본 oklch 값을 sRGB로 변환해 WCAG 공식으로 계산했습니다.

| 문제 | 근거 | 조치 |
|---|---|---|
| 차트 색이 사실상 2가지뿐 | chart-1과 chart-5의 색 차이 ΔE_ok 0.8. 눈으로 구분할 수 없음 | 범주색 5개를 새로 정의 (`--eidos-cat-1~5`) |
| chart-3, chart-4가 배경에 묻힘 | 배경 대비 라이트 1.35 / 1.37, 다크 1.16 / 1.13 | 범주색에서 제외하고 면 채우기(`--eidos-fill-*`)로만 사용 |
| 라이트 모드 보라가 선·점으로 쓰기에 흐림 | chart-2 배경 대비 2.77 (그래픽 최소 기준 3:1 미달) | 라이트에서만 `oklch(0.56 0.16 290)`로 진하게 (4.69) |
| 오류·성공·경고 색이 없음 | 라이트 destructive가 거의 검정(`#141413` 계열) | `--eidos-success`, `--eidos-danger`, `--eidos-warning` 추가. 코드 디프, 상태 전이, 장애 설명에 필요 |
| 강조색 위 흰 글씨가 작은 글자에는 부족 | 라이트 primary 위 흰 글씨 3.9 (본문 기준 4.5 미달) | 강조색 배경 위 글자는 18px 이상 또는 굵게만 사용 |
| 웹폰트 의존 | Outfit, Geist Mono는 외부 폰트이고, Outfit은 한글 글리프가 없음 | 기본은 시스템 폰트 스택. Outfit은 선택 사항으로, 쓸 때는 파일 안에 내장 |
| 앱 전용 토큰이 많음 | sidebar, popover, input 등 | 제외 |

## 토큰

```css
:root {
  /* 바탕 */
  --eidos-bg:          oklch(0.9818 0.0054 95.0986);   /* #faf9f5 */
  --eidos-fg:          oklch(0.3438 0.0269 95.7226);   /* #3d3929  대비 10.98 */
  --eidos-surface:     oklch(0.9665 0.0067 97.3521);   /* 카드, 노드 */
  --eidos-surface-fg:  oklch(0.1908 0.0020 106.5859);
  --eidos-muted-fg:    oklch(0.5341 0.0078 97.4503);   /* 보조 글자  대비 4.92 */
  --eidos-border:      oklch(0.8847 0.0069 97.3627);

  /* 강조: 한 장면에서 시선이 가야 할 단 하나 */
  --eidos-accent:      oklch(0.6171 0.1375 39.0427);   /* #c96442 테라코타  대비 3.7 */
  --eidos-accent-fg:   oklch(1 0 0);

  /* 범주색: 비교 대상, 행위자, 데이터 계열 (순서대로 사용) */
  --eidos-cat-1:       var(--eidos-accent);             /* 테라코타 */
  --eidos-cat-2:       oklch(0.56 0.16 290);            /* 보라   대비 4.69 */
  --eidos-cat-3:       oklch(0.58 0.09 195);            /* 청록   대비 3.90 */
  --eidos-cat-4:       oklch(0.56 0.13 255);            /* 파랑   대비 4.44 */
  --eidos-cat-5:       oklch(0.60 0.11 115);            /* 올리브 대비 3.67 */

  /* 면 채우기: 영역, 배경 띠, 하이라이트 */
  --eidos-fill-warm:   oklch(0.8816 0.0276 93.1280);   /* 원본 chart-3 */
  --eidos-fill-cool:   oklch(0.8822 0.0403 298.1792);  /* 원본 chart-4 */

  /* 의미색 */
  --eidos-success:     oklch(0.56 0.13 150);            /* 대비 4.17 */
  --eidos-danger:      oklch(0.56 0.19 27);             /* 대비 4.86 */
  --eidos-warning:     oklch(0.60 0.13 70);             /* 대비 3.85 */

  /* 형태 */
  --eidos-radius:      1rem;
  --eidos-radius-sm:   0.5rem;                          /* 다이어그램 노드, 태그 */
  --eidos-shadow:      0 1px 3px 0 hsl(0 0% 0% / 0.10), 0 1px 2px -1px hsl(0 0% 0% / 0.10);

  /* 글꼴 (외부 요청 없음) */
  --eidos-font-sans:   system-ui, -apple-system, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif;
  --eidos-font-mono:   ui-monospace, "SF Mono", Menlo, Consolas, monospace;
}

@media (prefers-color-scheme: dark) {
  :root {
    --eidos-bg:          oklch(0.2679 0.0036 106.6427);  /* #262624 */
    --eidos-fg:          oklch(0.9576 0.0027 106.4494);  /* 대비 13.4 */
    --eidos-surface:     oklch(0.2928 0.0018 106.5092);
    --eidos-surface-fg:  oklch(0.9818 0.0054 95.0986);
    --eidos-muted-fg:    oklch(0.7713 0.0169 99.0657);   /* 대비 7.36 */
    --eidos-border:      oklch(0.3618 0.0101 106.8928);

    --eidos-accent:      oklch(0.6724 0.1308 38.7559);   /* #d97757  대비 4.86 */
    --eidos-accent-fg:   oklch(0.1908 0.0020 106.5859);  /* 대비 5.9 */

    --eidos-cat-2:       oklch(0.6898 0.1581 290.4107);  /* 대비 5.20 */
    --eidos-cat-3:       oklch(0.72 0.10 195);           /* 대비 6.38 */
    --eidos-cat-4:       oklch(0.72 0.12 255);           /* 대비 6.11 */
    --eidos-cat-5:       oklch(0.74 0.11 115);           /* 대비 6.71 */

    --eidos-fill-warm:   oklch(0.2130 0.0078 95.4245);
    --eidos-fill-cool:   oklch(0.3074 0.0516 289.3230);

    --eidos-success:     oklch(0.72 0.14 150);           /* 대비 6.46 */
```

괄호 안 대비는 해당 모드 배경(`--eidos-bg`) 대비입니다. 글자는 4.5 이상, 선·점·아이콘은 3 이상이 기준입니다.

## 사용 가이드 (권장)

1. **강조색은 한 장면에 하나만 씁니다.** 랙 포커스, 하이라이트 스윕, 프리즈 프레임 주석처럼 "지금 여기를 보라"는 곳에만 씁니다. 나머지는 `--eidos-fg`와 `--eidos-muted-fg`로 둡니다.
2. **범주색은 1번부터 순서대로 씁니다.** 스플릿 스크린의 왼쪽과 오른쪽, 시퀀스 다이어그램의 행위자, 차트 계열이 여기에 해당합니다. 5개로 부족하면 아래 "색을 더 만들 때"를 따라 늘립니다. 단, 8개를 넘어가면 색만으로는 구분이 어려우니 범주를 묶거나 나눠 보여주는 방법도 검토합니다.
3. **의미색은 의미가 있을 때만 씁니다.** 코드 디프의 추가와 삭제, 성공과 실패 상태, 경고에만 씁니다. 장식으로 쓰지 않습니다.
4. **강조색과 danger를 한 장면에 같이 쓰지 않습니다.** 둘 다 붉은 계열(색상각 39°와 27°)이라 헷갈립니다. 오류를 다루는 장면에서는 강조를 `--eidos-cat-4`(파랑)로 바꿉니다.
5. **경고색은 라이트 모드에서 글자로 쓰지 않습니다.** 대비가 3.85라서 아이콘, 배경 띠, 테두리로만 씁니다.
6. **색만으로 구분하지 않습니다.** 범주에는 라벨, 위치, 선 모양(실선/점선)을 함께 씁니다.

## 색을 더 만들 때

범주가 많거나, 주제에 어울리는 색(예: 브랜드 색, 지도의 바다색)이 필요하면 새 색을 만들어도 됩니다. 톤을 유지하는 요령은 다음과 같습니다.

- **oklch에서 명도(L)와 채도(C)는 기존 범주색과 비슷하게 두고 색상(H)만 바꿉니다.** 라이트는 L 0.56~0.62, C 0.09~0.16, 다크는 L 0.68~0.76 정도입니다.
- 기존 색과 색상각이 30° 이상 떨어지게 고릅니다.
- 같은 계열 안의 세부 항목은 같은 색상에서 명도만 바꾼 단계색으로 표현합니다.
- 선과 점은 배경 대비 3 이상, 글자는 4.5 이상을 맞추는 것이 좋습니다.

## 테마 교체

기법이 기본 색을 `--eidos-*` 변수로 참조해 두면, 사용자가 자기 브랜드 색을 원하면 이 블록만 바꾸면 됩니다. tweakcn의 다른 테마도 위 표처럼 이 토큰 이름으로 옮겨 쓸 수 있습니다.
