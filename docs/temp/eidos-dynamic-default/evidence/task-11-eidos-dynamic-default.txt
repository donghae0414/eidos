1. WHAT CHANGED
runtime/eidos-stage.js, Camera region only (3 hunks):
  - camera.to(target, {arc}): arc is a number from 0 to 1, default 0. A non-number, NaN or out-of-range
    value pushes "camera.to arc must be a number from 0 to 1, got <v>" to __eidosErrors; numbers clamp to
    [0, 1] and anything else becomes 0, the plain move.
  - Camera.mix(a, b, e, arc = 0, W = 0, H = 0): with arc > 0 the view extent v = 1/s widens by h*sin(pi*e),
    so the move zooms out, travels and zooms in. h = arc * max(0, fit - sqrt(va*vb)) and
    fit = max(|dx|/W, |dy|/H) + (va + vb)/2. Position follows the accumulated extent in closed form, the
    rule the plain mix already uses, so screen-space travel speed stays even. With no lift (arc 0, or both
    endpoints already fit one view) the original expression runs unchanged, so existing camera moves are
    bit-identical.
  - Camera.stateAt passes kf.arc, W and H to mix, so s.scene, s.spoke and s.back with via "camera" and
    with: {arc} fly as well.
skills/eidos-camera/techniques/<id>/{card.md, technique.js, template.html} for the six ids. Every card has
kind technique, priority P1, group eidos-camera, the cross-dissolve section order and a "장면 관계" line.
Every template.html is a standalone Korean developer topic that loads ../../../../runtime/* and ./technique.js.
  - crane-up: fx({from, context, tilt = 12, rig = world's first child, openZoom, pad, introDur}) opens on
    "from" with the rig tilted back (rotateX pivoted on that detail); rise({to = "world", dur = 2.2}) climbs
    and pulls back, flattens the tilt over 85% of the rise and reveals the context lowest element first.
    Reduced motion: tilt 0, so no rotateX track and no transform-origin. Template: fs.readFile() down to
    sys_read through Node.js, libuv and libc.
  - ken-burns: fx({to, from, in, dur = 4.5, ease, pad}) and drift(to, opts). A rect is [x, y, w, h] as
    fractions of "in" (default world's first child), framed with pad 0; selectors, elements, {x, y, w, h}
    and "world" work too. A bad rect pushes an error and falls back to the whole "in" box. Template: CPU
    flame graph, loadConfig 41% and compileTemplate 22%.
  - parallax: fx({layers = [data-parallax] elements, axis}) binds layers to camera translation in an onSeek
    hook: translate(-depth*dx, -depth*dy), dx and dy being the camera offset from home. Screen speed is
    (1 + depth) x camera speed; depth -1 pins to the screen. A depth that is not a number >= -1 pushes an
    error and that layer is skipped. Template: pace layering (UI weekly, API quarterly, schema yearly, infra
    every few years).
  - fly-to: fx({target, arc = 0.6, dur = 2.4, zoom, pad, ease, route, from, bend = 0.2, reveal}) is camera.to
    with arc, plus an optional route path drawn as a quadratic curve computed in the route SVG's own box and
    an arrival reveal. Template: CDN cache miss, Seoul edge to us-east-1 and back.
  - speed-ramp: fx({focus = [a, b], rate = 0.5, at = last stop, dur = tl.end - at}) is a thin wrapper over
    tl.ramp: three ramps (fast, slow, fast) keep display time equal to source time at both window edges, so
    stops and tweens outside the window stay put; fast = (dur - F) / (dur - F/rate). It rejects with an error
    and no ramp: focus outside the window, rate outside (0, 1), focus/rate >= dur, a stop or ramp inside the
    window, non-numbers. Template: lost update, two orders both read stock 1 and write 0.
  - time-lapse: fx({frames, render(frame, u), counter, format, from, to, dur = 4, ease = "linear"}) and
    to(u, opts). Progress maps to source time u; render gets the last frame with at <= u (the first frame
    before the first record), found by binary search. Unsorted or empty frames, a non-function render or a
    non-finite from or to push an error and record nothing. Template: HPA autoscaling over one day.
