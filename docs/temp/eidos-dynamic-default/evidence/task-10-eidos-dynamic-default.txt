IMPLEMENTED BEHAVIOR AND AUTHORING DECISIONS
screen-dive: FLIP composition fits the inner full-frame scene into the
device/window screen, zooms it to the full frame, and supports out:true.
Layout measurements run in onLayout. Reduced motion cuts at halfway.
zoom-through: SVG text mask expands exponentially to the configured
50-200x scale. Glyph stroke dilation opens hollow counters and inter-letter
gaps rather than allowing them to re-cover already revealed content.
Reduced motion uses a halfway cut, without a mask.
cross-cutting: technique, not transition. beats contains numeric [a,b]
progress checkpoints in [0,1]; even beats show pane A, odd beats show B.
Both tracks' progress is recorded at each beat. Optional descendant markers
render progress bars and percentages. Integer beat boundaries are snapped.
pixel-dissolve: transition. cols x cols CSS grid cells cover the actual
incoming scene with clipped static outgoing-scene clones. Fisher-Yates
using Eidos.rng(seed) runs only at build time; rank < floor(p*N) disappears.
Default easing is linear. No canvas. The card documents the static-source,
class-based-style requirement for clones. Reduced motion builds no grid
and cuts at p=0.5.
cutaway: technique wrapping s.spoke, a build(stage) callback, and s.back.
The card documents loading its chosen transition, authoring a hub stop
first, and preserving hub state. Template uses cross-dissolve dur 0.7.
All five reject unknown own option keys and report '<id>: ...' to
__eidosErrors before throwing. Explicit CSS values are used for resets.
Zero-duration tracks in the four timed techniques preserve t === start,
then apply the final state only at t > start, without adding a duration floor.

MECHANISM AND FIX
The original wrapper put back() immediately after the detail stop. A transition
whose effective duration is zero therefore gave detail and ret-detail the same
time, while strict t > start tracks still showed detail at the return stop.
The previous draft separated those times, but its zero-duration cross-dissolve
entry still overwrote the hub at the hub stop. Its saved after.log failed there.
Attempt 2 retains the draft's distinct return timing and additionally guards
zero-duration entry tracks at t <= start. Actual transition dur stays unchanged:
there is a 0.1 s gap before back(), and only zero-duration returns receive a
0.1 s settling interval before their stop. The runtime's inclusive hub restore
and strict cut entry rules therefore no longer contend at a shared stop.

Accepted via: cut, camera, cross-dissolve, jump-cut, smash-cut, dip-to-color, iris.
Camera requires a detail element nested inside the hub. Separate full-frame
camera roots cannot restore their visibility through the camera-only runtime
path, so they fail descriptively before construction. Other transitions with
non-restoring transforms/masks/clones, or non-reversible entry options, are
rejected with a cutaway-prefixed throw and matching __eidosErrors entry.
The Korean card documents the supported set, rejected set, zero durations,
entry boundary, return gap, and nested-camera requirement.
Only cutaway/card.md and cutaway/technique.js need production changes.
