# 스피드램프 (Speed Ramp)

## 전달하는 의미
**지나가는 과정은 빨리, 결정적인 순간은 천천히.** 한 구간 안에서 재생 속도를 바꿔 덜 중요한 이동은 빨리 감고, 핵심 순간(두 요청이 같은 값을 읽는 순간, 이벤트 루프 한 틱)만 늘려 보여 줍니다. 시청자는 속도가 느려지는 것만으로 "지금이 중요하다"를 압니다.

**장면 관계:** 장면 안의 시간 강조. 화면 배치는 그대로이고 시간만 바뀝니다. `via`가 아니라 `s.fx`로 부릅니다.

## 언제 쓰나
- 빠르게 지나가는 과정 속 한순간이 원인일 때: 레이스 컨디션, 갱신 손실, 데드락이 생기는 순서, 타임아웃 직전
- 한 스톱 구간 안에 긴 준비 과정과 짧은 핵심이 함께 있을 때
- 슬로모션만 필요할 때 (앞뒤 준비 구간을 짧게 두면 사실상 슬로모션만 남습니다)

## 피할 때
- 핵심 순간을 스톱으로 나눠도 될 때. 스톱에서 멈추는 쪽이 더 분명합니다. 스피드램프는 흐름을 끊지 않고 강조할 때 씁니다.
- 한 작품에서 여러 번. 매번 느려지면 강조가 사라집니다.
- 구간 안에 스톱이 있을 때. 속도 곡선은 스톱과 스톱 사이 한 구간 안에서만 씁니다.

## 사용법
```js
// 먼저 장면을 원래 시간(초)으로 짭니다: 0~1.6 요청 이동, 1.6~3.2 읽기·쓰기 교차, 3.2~4.8 응답
const T = stage.tl.end;
stage.tl.tween(".req", { x: [0, 300] }, { at: T, dur: 1.6 });
// ... 핵심 순간 tween들 (T + 1.6 ~ T + 3.2) ...
stage.fx("speed-ramp", { at: T, dur: 4.8, focus: [T + 1.6, T + 3.2], rate: 0.5 });
stage.tl.stop("둘 다 재고 1을 읽고 0을 씁니다");
```
`[at, at + dur]` 구간의 길이는 그대로 두고, `focus` 구간을 `rate`배로 늘린 만큼 앞뒤를 빨리 감습니다. 그래서 구간 밖의 스톱 시각과 tween은 하나도 밀리지 않습니다. 내부적으로는 `tl.ramp`를 세 번(빠르게, 느리게, 빠르게) 부르는 얇은 래퍼입니다. 구간 끝이 타임라인 끝보다 뒤면 타임라인을 구간 끝까지 늘립니다.

`focus`는 원래 시간(tween을 짤 때 쓴 시각)으로 적습니다. 빨라지는 배율은 자동으로 정해집니다: `fast = (dur - F) / (dur - F / rate)`, F는 focus 길이입니다. 느려진 focus가 구간 안에 들어가야 하므로 `F / rate < dur`여야 합니다. 앞뒤가 지나치게 빨라지지 않게 구간을 focus의 3배쯤으로 잡으세요(`rate 0.5`이면 앞뒤 2배). 조건이 맞지 않거나(focus가 구간 밖, rate가 0~1 밖, 구간 안에 스톱이나 다른 ramp가 있음) 유한수가 아니거나 알 수 없는 옵션이 있으면 `__eidosErrors`에 `speed-ramp: ...` 오류를 남기고 예외를 던집니다. 잘못된 호출은 ramp를 기록하지 않습니다.

재생과 `goto` 애니메이션에서는 느린 구간이 `rate`보다 더 느리게 보입니다. 런타임 전송은 표시 시간 1초를 `1 / rate`초에 걸쳐 지나가고, 그 1초 동안 tween은 `rate`초만큼 진행하므로 화면 속도는 대략 `rate²`배입니다(rate 0.5이면 체감 1/4). 그래서 화면에는 배율 숫자 대신 "슬로모션", "빨리 감기"처럼 적습니다.

## 파라미터
| 이름 | 기본값 | 설명 |
|---|---|---|
| `focus` | (필수) | `[a, b]` 원래 시간. 느리게 보여 줄 핵심 구간 |
| `rate` | `0.5` | focus 구간의 속도. 0보다 크고 1보다 작게 |
| `at` | 마지막 스톱 시각 | 속도 곡선 구간의 시작 |
| `dur` | `tl.end - at` | 구간 길이. 이 길이는 바뀌지 않습니다 |

반환값: `{ start, end, slowFrom, slowTo, rate, fast }`. `slowFrom`과 `slowTo`는 느린 구간의 표시 시각입니다.

## 변형
- **프리즈:** 한순간을 완전히 멈추려면 `stage.tl.ramp({ at, dur, rate: 0 })`를 직접 씁니다. 이때는 그 뒤 원래 시간이 밀리므로 스톱 위치를 함께 맞춰야 합니다. 대부분은 freeze-frame 기법이 더 쉽습니다.
- **슬로모션만:** focus 앞뒤의 준비 구간을 아주 짧게 두면 앞뒤는 순식간에 지나가고 슬로모션만 남습니다.

## reduced-motion
스톱 사이를 즉시 이동하므로 속도 변화는 보이지 않고 스톱의 화면은 같습니다. 입력 검사와 오류 보고는 똑같이 동작합니다.
