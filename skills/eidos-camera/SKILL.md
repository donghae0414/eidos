# EIDOS 카메라 기법

카메라는 world 전체를 움직여 **어디를 볼지**를 정합니다. 장면 안의 내용은 그대로 두고 시선만 옮기므로, 공간 관계가 있는 설명(구조, 경로, 계층)에 씁니다.

| id | 의미 | 언제 | kind | priority |
|---|---|---|---|---|
| `establishing-shot` | 이것은 전체 중 여기에 있다. | 아키텍처, 인프라, 조직도처럼 "어디에 있는가"가 중요한 설명의 첫 장면<br>사용자가 알고 있는 하나(서버, 화면, 파일)에서 출발해 낯선 전체로 확장할 때<br>전체를 보여준 뒤 다음 설명 대상으로 다시 들어가고 싶을 때 (카드의 포커스 변형) | technique | P0 |
| `freeze-frame` | 바로 이 순간이다. | 버그나 장애의 원인이 "특정 순간의 상태"일 때: 경쟁 상태, 데드락, 중복 결제<br>tracking이나 sequence-message 도중 한 지점을 멈춰 짚고 싶을 때<br>결과보다 과정 중간의 값이 중요할 때 (두 스레드가 읽은 값, 그 순간의 큐 길이) | technique | P0 |
| `pan` | 같은 크기로, 순서대로 읽는다. | 단계가 5개 이상인 가로 흐름: CI/CD, 데이터 파이프라인, 요청 처리 단계, 연혁<br>세로로 쌓인 계층: 네트워크 계층(OSI), 콜 스택, 조직도 한 갈래 (`axis: "y"`, 틸트)<br>전체를 먼저 보여준 뒤(설정숏) 한 칸씩 읽어 갈 때 | technique | P0 |
| `rack-focus` | 이제는 이쪽을 보라. | 한 화면에 놓인 둘을 차례로 설명할 때: 동기 vs 비동기, 클라이언트 코드 vs 서버 코드<br>다이어그램과 코드처럼 겹쳐 놓은 두 층 사이를 오갈 때<br>비교 장면에서 "지금 말하는 쪽"을 표시할 때 (split-screen의 `focus`와 같은 역할을 겹친 배치에서) | technique | P0 |
| `tracking` | 이것을 따라가라. | 요청 흐름: 브라우저 → CDN → 서버 → DB<br>데이터 파이프라인에서 한 레코드의 여정, 메시지 큐를 지나는 이벤트<br>사용자 여정(가입 → 결제 → 알림)을 한 사람의 시점으로 | technique | P0 |
| `zoom-in` | 이 부분을 자세히 본다 | 전체 구조를 보여준 뒤 한 구성 요소의 내부를 설명할 때 (아키텍처 → 모듈, 화면 → 버튼)<br>세부 정보를 처음엔 작게 숨겨 두고, 다가갔을 때 드러내고 싶을 때 (`reveal`)<br>같은 화면에서 여러 대상을 차례로 설명할 때 (카드의 복귀 변형 후 다른 대상으로 다시 줌인) | technique | P0 |
| `crane-up` | 이 작은 것은 저 높은 구조의 맨 아래에 있다. | 세부가 **세로로 쌓인 구조의 아래쪽**에 있을 때: 호출 스택(앱 → 런타임 → libc → 커널), 네트워크 계층, 인프라 계층, 조직도의 말단<br>"이 낮은 수준의 일은 사실 위에서 시킨 것"이라는 인과를 보여줄 때 (시스템 콜이 어느 코드에서 왔는지)<br>첫 장면에서 사용자가 아는 바닥의 한 점에서 시작해 전체 높이를 드러낼 때 | technique | P1 |
| `fly-to` | 멀리 떨어진 두 곳이 이어져 있고, 그 사이는 멀다. | 확대한 상태에서 멀리 있는 다른 대상으로 옮겨 갈 때: 엣지 → 원본 서버, 서비스 A → 다른 리전의 서비스 B, 지도 위 두 도시<br>거리 자체가 설명의 일부일 때 (지연 시간, 홉 수, 리전 간 비용)<br>그냥 `camera.to`로 옮기면 화면이 빠르게 미끄러져 어디에서 어디로 갔는지 놓칠 때 | technique | P1 |
| `ken-burns` | 멈춰 있는 그림을 눈으로 따라 읽는다. | 한 장으로 완성된 그림을 순서대로 읽어 줄 때: 플레임 그래프의 탑, 트레이스 워터폴의 긴 구간, 큰 다이어그램의 구역<br>그림 안 영역을 요소가 아니라 비율로 가리키고 싶을 때 (`[x, y, w, h]`, 0~1)<br>요소 단위 애니메이션이 없는 정적인 그림에 움직임을 줄 때 | technique | P1 |
| `parallax` | 멀리 있는 것은 느리게, 가까운 것은 빠르게 지나간다. | 층마다 수명이나 변경 속도가 다를 때: 페이스 레이어링(UI → API → 스키마 → 인프라), 캐시 계층, 기술 스택<br>카메라가 옆으로 훑는 동안 바탕 맥락(리전, 조직, 시대)은 거의 그대로 두고 세부만 지나가게 할 때<br>제목, 범례, 층 이름을 카메라 이동 중에도 화면에 남기고 싶을 때 (`depth: -1`) | technique | P1 |
| `speed-ramp` | 지나가는 과정은 빨리, 결정적인 순간은 천천히. | 빠르게 지나가는 과정 속 한순간이 원인일 때: 레이스 컨디션, 갱신 손실, 데드락이 생기는 순서, 타임아웃 직전<br>한 스톱 구간 안에 긴 준비 과정과 짧은 핵심이 함께 있을 때<br>슬로모션만 필요할 때 (앞뒤 준비 구간을 짧게 두면 사실상 슬로모션만 남습니다) | technique | P1 |
| `time-lapse` | 긴 시간이 압축되어 흐르고, 그동안 상태는 이렇게 바뀌었다. | 시간에 따라 쌓이거나 출렁이는 상태: 오토스케일링 하루, 커밋 히스토리, 디스크 사용량, 큐 길이, 에러율<br>데이터가 이미 시각별 기록으로 있을 때 (`frames: [{ at, ... }]`)<br>원인과 결과 사이에 시간 차가 있을 때 (트래픽이 줄고 한 시간 뒤에 파드가 줄어듦) | technique | P1 |
| `dolly-zoom` | 대상은 그대로인데 그 뒤의 세계가 달라졌다. | 같은 쿼리, 같은 API, 같은 설정이 규모 때문에 다르게 동작하는 순간 (개발 DB → 운영 DB, 사용자 10명 → 100만 명)<br>문제를 해결한 뒤 거리가 다시 가까워지는 반전 (인덱스, 캐시, 샤딩 뒤에 배경 이동을 반대로)<br>가장 중요한 깨달음 하나에만. 효과가 강해서 아껴 씁니다. | technique | P2 |
| `fpv-flight` | 요청(데이터, 사용자)의 눈으로 경로를 직접 지나간다. | 요청 경로: 브라우저 → DNS → CDN → 로드 밸런서 → API → DB<br>계층을 차례로 통과하는 설명: OSI 계층, 미들웨어 체인, 컴파일 파이프라인<br>단계마다 비용이 쌓일 때. 관문에 `+12ms`처럼 값을 달고, 누적 값은 화면 밖 레일에 둡니다. | technique | P2 |
| `infinite-zoom` | 큰 숫자의 원인은 아주 작은 곳에 있다. | 원인 추적(드릴다운): 지표 → 팀 → 서비스 → 모듈 → 함수<br>계층 구조 소개: 클러스터 → 노드 → 파드 → 컨테이너, 저장소 → 패키지 → 파일<br>규모 설명: 데이터센터 → 랙 → 서버 → 칩 (Powers of Ten) | technique | P2 |
| `orbit` | 같은 것을 돌려 보면 다른 사실이 보인다. | 겹쳐 있는 층을 정면 → 비스듬히 → 옆으로 보여 줄 때: 계층형 아키텍처, 네트워크 스택, L1/L2/DB 캐시 층<br>정면에서는 안 보이는 관계를 옆면 평면에 두고, 돌아서 드러낼 때: 의존 방향, 요청 순서<br>한 개념의 여러 면을 차례로 볼 때: 평면을 원형으로 세운 턴테이블 (카드의 변형 참고) | technique | P2 |

## 사용법

1. 고른 기법의 `techniques/<id>/card.md`를 읽습니다. 옵션과 "피할 때"가 적혀 있습니다.
2. `techniques/<id>/template.html`에서 마크업 구조(어떤 요소가 world 바로 아래에 와야 하는지 등)를 확인합니다.
3. 작업 HTML에 `runtime/eidos-stage.css`, `runtime/eidos-stage.js`, 필요한 `technique.js`를 절대 경로로 넣고, `node scripts/inline.mjs`로 한 파일로 묶습니다.

## 카메라 공통 규칙

- 카메라 대상은 선택자, 요소, `{x, y, w, h}` 사각형, `{x, y, s}` 상태, 또는 레이아웃 시점에 계산되는 함수입니다.
- 화면 크기에 따라 달라지는 좌표는 `stage.onLayout(fn)`에서 계산합니다. 런타임은 onLayout을 먼저 실행하고 카메라 목표를 계산합니다.
- 카메라 이동 뒤에는 `stage.camera.to("world")`로 전체를 다시 보여주는 stop을 두면 시청자가 위치를 잃지 않습니다.
- 확대해서 보여줄 세부 글자는 작게 써도 됩니다. 확대 후 크기가 기준입니다.

## 카메라·시간 변형

- 더치 앵글은 `stage.camera.to(target, {roll: 8})`처럼 `roll`로 기울입니다.
- 슬로모션은 `s.speed(0.5)`로 전체 재생을 늦춥니다. 특정 구간만 바꾸려면 speed-ramp 카드와 `tl.ramp`를 씁니다.
