브랜치 전략

Git Flow는 네 단계로 돌아갑니다

역할이 다른 브랜치 다섯 종류가 정해진 순서로 합쳐집니다.

main develop feature/* release/* hotfix/*
1

feature/* 에서 기능을 개발한다

develop에서 분기합니다. 기능 하나에 브랜치 하나, 끝나면 PR을 엽니다.

2

리뷰가 끝나면 develop 으로 머지한다

다음 릴리스에 들어갈 기능이 develop에 차곡차곡 쌓입니다.

3

release/* 에서 배포를 준비하고 main 에 머지한다

버전 번호와 버그 수정만 다룹니다. 끝나면 main과 develop 양쪽에 머지하고 태그를 답니다.

4

운영 장애는 hotfix/* 로 바로 고친다

main에서 분기해 수정하고, 역시 main과 develop 양쪽에 머지합니다.
