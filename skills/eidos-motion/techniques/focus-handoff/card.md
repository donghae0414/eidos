# 초점 넘기기 (Focus Handoff)

**장면 관계:** 한 장면 안에서 이미 보이는 항목들 사이로 "지금 말하는 항목"을 옮길 때 씁니다. 장면 경계의 `via` 값이 아니므로 `s.fx`로 부릅니다.

## 전달하는 의미
**이제 이 항목 차례다.** 항목은 전부 보이는 채로, 하나만 테두리와 옅은 바탕이 켜지고 나머지는 흐려집니다. 초점이 다음 항목으로 넘어가면 앞 항목은 다시 흐려지므로, 화면이 바뀌지 않아도 해설이 어디까지 왔는지와 읽는 순서가 보입니다. 배치가 끝까지 그대로라 "전체 중의 이것"이라는 관계가 유지됩니다.

## 언제 쓰나
- 셋에서 여섯 개 항목을 차례로 설명할 때. 항목마다 stop 하나가 생기고, `labels`로 캡션을 붙입니다
- 이미 등장한 목록, 단계, 다이어그램 노드를 두 번째로 훑으며 하나씩 짚을 때
- 코드 블록의 줄 묶음처럼 "지금 읽는 범위"를 옮길 때
- 결론에서 앞 항목을 다시 가리킬 때 (`order: [0, 1, 2, 0]`처럼 같은 번호를 다시 넣음)

## 피할 때
- 항목이 아직 보이지 않을 때. 등장은 stagger-reveal의 몫이고, 이 기법은 이미 보이는 것 사이에서 초점만 옮깁니다
- 항목이 여섯 개를 넘을 때. 한 바퀴 도는 동안 앞 내용이 잊힙니다. 장면을 나누거나 묶어서 보여 주세요
- 두 항목을 동시에 켜고 싶을 때. 초점은 언제나 하나입니다. 둘을 나란히 비교하려면 split-screen이나 rack-focus를 쓰세요
- 겹쳐 놓은 두 층 사이를 오갈 때. 그것은 rack-focus(블러와 카메라의 느낌)입니다. 초점 넘기기는 블러도 카메라도 없이 나란한 항목 사이에서 테두리와 불투명도만 바꿉니다

## 사용법
```html
<ol class="steps">
  <li class="step">토큰화</li>
  <li class="step">프리필</li>
  <li class="step">디코딩</li>
</ol>
```
```js
s.tl.stagger(".step", { opacity: [0, 1], y: [12, 0] }, { dur: 0.5, overlap: 0.6, ease: "out" });
s.tl.stop("추론은 세 단계로 돕니다");
const fh = s.fx("focus-handoff", {
  targets: ".step",
  labels: ["1 토큰화: 문장을 토큰 id로", "2 프리필: KV 캐시를 채움", "3 디코딩: 토큰 하나씩 생성"],
});                                                  // 항목마다 stop 하나, 캡션은 labels
fh.restore();                                        // 모두 다시 또렷하게 (선택)
s.tl.stop("세 단계를 한 번에");
```
**테두리.** 기법이 항목마다 `span.eidos-focus`를 첫 자식으로 넣습니다. 항목 바깥 6px에 강조색 테두리와 옅은 강조색 바탕을 가진 상자이며, 항목의 둥근 모서리를 따라갑니다. 항목에 `position: relative`(static일 때만)와 `isolation: isolate`를 걸고 테두리는 내용 뒤(`z-index: -1`)에 둡니다. 항목에 불투명한 배경이 있으면 바탕색은 가려지고 테두리만 보입니다.

항목의 `opacity`와 `scale`은 이 기법이 씁니다. 켜진 항목은 1.02배로 살짝 떠오르고(`overshoot`), 나머지는 `dimTo`로 흐려집니다. 색은 CSS 변수 `--eidos-accent`를 따릅니다.

## 파라미터
| 이름 | 기본값 | 설명 |
|---|---|---|
| `targets` | (필수) | 초점을 주고받을 항목들 (DOM 순서) |
| `order` | `[0, 1, …, n-1]` | 초점이 머무는 항목 번호의 순서. 같은 번호를 다시 넣으면 다시 짚습니다. 생략하면 DOM 순서대로 한 번씩 |
| `stopEach` | `true` | 항목마다 `tl.stop`을 넣습니다. `false`면 멈추지 않고 `hold`만큼 머문 뒤 다음으로 넘어갑니다 |
| `labels` | 없음 | 항목마다 stop의 캡션 (`stopEach: true`일 때만). 모자라면 빈 캡션, `order`보다 많으면 오류 |
| `hold` | `0.5` | `stopEach: false`일 때 켜진 채로 머무는 시간(초). 해설 한 문장 길이에 맞춥니다 |
| `dimTo` | `0.45` | 초점이 없는 항목의 불투명도. 0.25 아래로 내리면 어두운 배경에서 읽히지 않습니다 |
| `dur` | `0.35` | 초점이 넘어가는 시간(초). 앞 항목이 흐려지는 것과 다음 항목이 켜지는 것이 같은 시각에 일어납니다 |
| `at` | 이어서 | 시작 시각 |

반환값: `{ start, end, items: [{ el, index, start, end }], restore({ at, dur }) }`. `restore`는 켜진 테두리를 끄고 모든 항목을 불투명도 1로 되돌립니다. 알 수 없는 옵션, 범위 밖 `order` 번호, `stopEach: false`와 `labels`의 조합, `stopEach: true`와 `hold`의 조합은 오류로 보고합니다.

## 변형
- **해설 길이로 자동 진행:** `stopEach: false, hold: 0.8`이면 stop 없이 항목이 0.8초씩 켜졌다 넘어갑니다. 해설 음성에 맞춘 영상용입니다
- **다시 짚기:** `order: [0, 1, 2, 0]`은 셋을 돈 뒤 첫 항목으로 돌아옵니다. "결국 핵심은 첫째"라는 결론에 맞습니다
- **일부만 훑기:** `order: [1, 3]`은 둘째와 넷째만 켭니다. 나머지는 처음부터 흐려진 채 남습니다
- **대비 조절:** 어두운 배경이나 작은 글자에서는 `dimTo: 0.55`로 흐려진 항목도 읽히게 둡니다

## reduced-motion
크기 변화 없이 불투명도만 바뀝니다(테두리 0 → 1, 항목 1 ↔ `dimTo`). 런타임이 stop 사이를 즉시 건너뛰므로 켜진 항목이 바로 바뀐 상태로 보입니다. 블러와 3D는 쓰지 않습니다.

## 같이 쓰기 좋은 기법
stagger-reveal(항목을 먼저 등장시킨 뒤 이 기법으로 두 번째 훑기), highlight-sweep(켜진 항목 안의 핵심어 한 번 더), spotlight(항목 바깥까지 모두 어둡게 할 때는 그쪽), rack-focus(겹친 두 층 사이의 초점은 그쪽)
