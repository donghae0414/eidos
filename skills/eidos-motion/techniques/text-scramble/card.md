# 텍스트 스크램블 (Text Scramble)

**장면 관계:** 한 장면 안에서 같은 자리의 값이 만들어지거나 바뀔 때 씁니다. 장면 경계의 `via` 값이 아니므로 `s.fx`로 부릅니다.

## 전달하는 의미
**이 값은 계산되어 나온다.** 글자가 무작위 글리프로 뒤섞이다가 자리마다 정답으로 굳으면, 값이 어딘가에서 계산되거나 해독되어 도착한다는 느낌을 줍니다. 해시, 토큰, ID처럼 사람이 정하지 않은 값에 맞습니다. `mode: "type"`은 한 글자씩 쳐 나가는 타자기로, 사람이 입력하는 명령이나 프롬프트를 보여 줍니다.

## 언제 쓰나
- 해시, 토큰, 키, 요청 ID처럼 계산 결과로 나오는 값 (decode)
- 입력이 조금 바뀌었는데 결과가 크게 바뀌는 장면. `keep`(기본)이면 같은 글자는 그대로 두고 바뀐 자리만 뒤섞입니다
- 터미널 명령, 검색어, 프롬프트처럼 사람이 치는 입력 (`mode: "type"`)

## 피할 때
- 숫자가 커지거나 줄어드는 변화. 크기 변화는 count-up이 정확합니다
- 긴 문장이나 문단. 뒤섞인 글자는 읽을 수 없으니 몇 단어 길이의 값에만 씁니다
- 비례폭 글꼴의 영문 긴 값. 글리프 폭이 달라 줄이 출렁입니다. 코드와 해시는 `var(--eidos-font-mono)`로 두세요 (한글 음절은 폭이 같아 괜찮습니다)

## 사용법
```html
<code class="val" id="in">hello</code>
<code class="val hash" id="out">2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824</code>
```
```js
s.fx("text-scramble", { targets: "#in", mode: "type" });           // 요소의 글자를 한 글자씩 친다
s.fx("text-scramble", { targets: "#out", dur: 1.6 });               // 빈 상태에서 해시를 해독한다
s.tl.stop("hello의 SHA-256");
s.fx("text-scramble", { targets: "#in", text: "Hello" });           // 직전 값에서 출발, 바뀐 자리만 뒤섞임
s.fx("text-scramble", { targets: "#out", text: "185f8db3…", order: "random" });
```
기본 `text`는 처음 불렀을 때 요소에 들어 있던 글자입니다. 같은 요소에 다시 부르면 직전 `text`에서 출발하므로 `from`을 따로 줄 필요가 없습니다. 기법이 요소 안을 세 span(보이는 글자, 커서, 아직 오지 않은 글자를 숨겨 자리만 차지하는 span)으로 바꾸므로, 상자 크기는 처음부터 최종 글자 기준이라 주변 레이아웃이 흔들리지 않습니다.

**글자 단위.** 글자는 `Intl.Segmenter`의 grapheme 단위로 나눕니다. 이모지(👩‍💻, 🇰🇷), 결합 문자(é = e + ◌́), 한글 음절이 반쪽으로 잘리지 않습니다. 공백과 줄바꿈은 뒤섞지 않고 제자리에 둡니다(여러 줄은 `white-space: pre-wrap`). 진행이 끝나는 순간(p=1)에는 원래 글자를 그대로 넣으므로 `textContent`가 `text`와 정확히 같습니다.

**뒤섞을 글리프.** 자리마다 원래 글자의 종류에서 고릅니다. 한글 음절은 한글 음절, 대문자는 대문자, 숫자는 숫자, 16진 값(8자 이상, a-f 포함)은 `0-9a-f`, 나머지는 기호입니다. 글리프는 `hash(seed, 자리, floor(p * bins))`로 정하므로 같은 시각이면 언제나 같은 글리프입니다.

## 파라미터
| 이름 | 기본값 | 설명 |
|---|---|---|
| `targets` | (필수) | 값을 보여 줄 요소들 |
| `text` | 요소의 처음 글자 | 도착할 글자. 배열이면 요소마다 |
| `from` | 직전 `text`, 없으면 `""` | 출발 글자 (`scramble` 모드) |
| `mode` | `"scramble"` | `"scramble"` 뒤섞이다 굳음 · `"type"` 한 글자씩 침 |
| `order` | `"ltr"` | 굳는 순서. `"ltr"` 왼쪽부터 · `"random"` 모든 자리가 함께 뒤섞이고 무작위 순서로 굳음 |
| `window` | `0.35` | 자리 하나가 뒤섞이는 구간 길이 (전체 진행 대비 0~1) |
| `rate` | `18` | 초당 글리프 교체 횟수. `bins`를 주면 그 값이 우선 |
| `keep` | `true` | 출발 글자와 도착 글자가 같은 자리는 뒤섞지 않음 |
| `glyphs` | 글자 종류별 | 뒤섞을 글리프 문자열을 직접 지정 (예: `"01"`) |
| `seed` | `1` | 글리프와 `random` 순서의 시드 |
| `caret` | `true` | `type` 모드에서 치는 동안 커서 표시 (깜빡이지 않음) |
| `reserve` | `true` | 아직 오지 않은 글자 자리를 미리 차지해 레이아웃 고정 |
| `dur` | scramble `1.2` · type `0.055 × 글자 수` (최소 0.4) | 시간(초) |
| `each` | `0.15` | 여러 요소일 때 다음 요소까지 간격(초) |
| `ease` | `"linear"` | 진행 이징. 글리프 교체 박자는 이징과 무관하게 일정 |
| `at` | 이어서 | 시작 시각 |

반환값: `{ start, end, items: [{ el, start, end, text }] }`

## 변형
- **해독(decode):** `from` 없이 처음 부르면 빈 자리에서 왼쪽부터 굳어 갑니다
- **바뀐 자리만:** 같은 요소에 새 `text`로 다시 부르면 다른 글자만 뒤섞입니다. 거의 모든 자리가 뒤섞이면 그 자체가 "통째로 바뀌었다"는 증거가 됩니다
- **타자기:** `mode: "type"`. 터미널 프롬프트 앞부분은 일반 텍스트로 두고 명령만 대상으로 잡으세요
- **이진 노이즈:** `glyphs: "01"`이면 비트가 뒤섞이는 느낌이 납니다

## reduced-motion
뒤섞임 없이 시작하는 순간(onset) 최종 글자가 통째로 나타납니다. 커서도 보이지 않습니다. 시작 전에는 출발 글자(또는 빈 자리)가 그대로 있습니다. 블러와 3D는 쓰지 않습니다.

## 같이 쓰기 좋은 기법
count-up(크기가 있는 숫자), highlight-sweep(굳은 값 속 핵심 부분 짚기), code-diff(바뀐 줄 전체를 보여 줄 때), kinetic-type(값이 아니라 문장을 강조할 때)
