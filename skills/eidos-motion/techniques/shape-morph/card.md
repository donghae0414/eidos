# 셰이프 모프 (Shape Morph)

**장면 관계:** 한 장면 안에서 같은 대상이 다른 구조가 될 때 씁니다. 장면 경계의 `via` 값이 아니므로 `s.fx`로 부릅니다.

## 전달하는 의미
**같은 것이 다른 구조가 됐다.** 도형이 끊기지 않고 다른 도형으로 바뀌므로, 두 그림이 서로 다른 물건이 아니라 한 대상의 두 상태라는 것을 보여 줍니다. 일자 배열이 링 버퍼로 휘거나 모놀리스 하나가 서비스 여러 개로 갈라지는 것처럼, 구조는 바뀌었지만 데이터는 그대로라는 말을 그림으로 합니다.

## 언제 쓰나
- 같은 데이터의 구조가 바뀔 때 (배열 → 링, 큐 → 스택, 표 → 막대)
- 하나가 여럿으로 갈라지거나 여럿이 하나로 합쳐질 때 (모놀리스 → 서비스, 샤드 병합). `pairs`로 어느 조각이 어느 조각이 되는지 정합니다
- 상태 아이콘이 다른 상태로 넘어갈 때 (재생 ▶ → 일시정지, 체크 → 경고)
- 바꿨던 구조를 다시 펼쳐 "사실은 이것"이라고 보여 줄 때. 같은 요소에 한 번 더 부르면 됩니다

## 피할 때
- 두 도형이 서로 다른 대상일 때. 모프는 "같은 것"이라고 말하므로 오해를 부릅니다. 단순 교체는 cross-dissolve나 jump-cut이 맞습니다
- 장면을 통째로 바꿀 때. 모프는 장면 안의 한 대상에 씁니다. 장면 경계에서 같은 모양을 잇는 것은 match-cut입니다
- 글자. 글리프 윤곽은 조각과 구멍이 많아 중간 모양이 지저분합니다. 글자는 text-scramble이나 kinetic-type을 쓰세요
- 아주 다른 위상(구멍 1개 ↔ 구멍 3개)을 짝 없이 이을 때. 중간에 겹치고 꼬입니다. `pairs`로 짝을 정하거나 장면을 나누세요

## 사용법
```html
<svg viewBox="0 0 560 440">
  <path id="buf" class="slot" d="M28 192H84V248H28Z M92 192H148V248H92Z"/>  <!-- 보이는 도형. 칸 하나 = 윤곽 하나 -->
  <defs><path id="ring" d="M280 52A168 168 0 0 1 ... Z M ... Z"/></defs>        <!-- 목표 모양은 defs에 -->
</svg>
```
```js
const m = s.fx("shape-morph", { from: "#buf", to: "#ring", dur: 1.4 }); // #buf의 d가 링으로 바뀐다
s.tl.stop("끝과 처음을 이으면 링 버퍼");
s.fx("shape-morph", { from: "#buf", to: rowD });                       // 같은 요소에 다시 부르면 직전 결과에서 출발
s.fx("shape-morph", { from: "#mono", to: "#svc", pairs: [[0, 0], [0, 1], [0, 2]] }); // 하나가 셋으로 갈라짐
```
`from`은 화면에 보이는 `<path>`이고, 이 요소의 `d` 속성이 바뀝니다. `to`는 목표 모양을 가진 `<path>` 선택자나 `d` 문자열입니다. 두 경로의 명령 구조가 달라도 됩니다(직선 사각형 → 호로 된 부채꼴). 기법이 경로를 윤곽(`M`으로 시작하는 조각)별로 나누고, 윤곽마다 같은 길이 간격의 점 128개로 다시 찍은 뒤 점끼리 보간합니다. 시작(p=0)과 끝(p=1)에는 원래 `d` 문자열을 그대로 씁니다.

**윤곽 짝.** 기본은 순서대로(0↔0, 1↔1…)입니다. 수가 다르거나 순서가 의미와 다르면 `pairs: [[from, to], ...]`로 정합니다. 짝이 없는 from 윤곽은 자기 중심으로 줄어들어 사라지고, 짝이 없는 to 윤곽은 자기 중심에서 자라납니다. 같은 from 윤곽을 여러 짝에 쓰면 갈라지고, 같은 to 윤곽을 여러 짝에 쓰면 합쳐집니다. 열린 윤곽(`Z` 없음, 끝점이 시작점과 다름)은 열린 윤곽과만, 닫힌 윤곽은 닫힌 윤곽과만 짝지을 수 있고 섞으면 오류입니다. 닫힌 윤곽은 감김 방향을 맞추고 시작점을 가장 덜 움직이는 회전으로 맞추므로 중간에 뒤집히거나 꼬이지 않습니다.

좌표는 `d` 값 그대로 읽습니다. 목표 path에 `transform` 속성을 붙이면 반영되지 않으니 좌표에 직접 넣으세요.

## 파라미터
| 이름 | 기본값 | 설명 |
|---|---|---|
| `from` | (필수) | 모양이 바뀌는 `<path>`. 여러 개면 `to`와 순서대로 짝을 짓습니다 |
| `to` | (필수) | 목표 `<path>` 선택자 또는 `d` 문자열 (`M`으로 시작) |
| `pairs` | 순서대로 | 윤곽 짝 `[[fromIndex, toIndex], ...]`. 모든 path 쌍에 같은 규칙을 씁니다 |
| `points` | `128` | 윤곽 하나를 다시 찍는 점 수. 큰 곡선이 각져 보이면 늘립니다 (최소 8) |
| `dur` | `1.2` | 시간(초) |
| `each` | `0` | `from`이 여러 개일 때 사이 간격(초) |
| `ease` | `"inOut"` | 이징 이름 또는 함수. `"pop"`처럼 넘치는 이징이면 목표를 살짝 지나쳤다 돌아옵니다 |
| `at` | 이어서 | 시작 시각 |

반환값: `{ start, end, items: [{ el, start, end, from, to }] }`. `from`, `to`는 그 구간의 시작과 끝 `d` 문자열입니다.

## 변형
- **갈라짐과 합쳐짐:** `pairs: [[0, 0], [0, 1], [0, 2]]`는 윤곽 하나가 셋으로, `[[0, 0], [1, 0], [2, 0]]`은 셋이 하나로 모입니다
- **펼쳐 보기:** 링으로 바꾼 뒤 같은 요소에 원래 `d`를 `to`로 다시 부르면 "메모리에서는 여전히 일자"처럼 실제 구조로 되돌아갑니다
- **함께 움직이는 표시:** 라벨이나 점은 같은 `at`, `dur`, `ease`로 `attr`(x, y, cx, cy) 트윈을 걸면 도형과 함께 갑니다. 반환값의 `start`, `end`를 쓰세요
- **색까지 바꾸기:** 색은 이 기법이 건드리지 않습니다. `s.tl.tween("#buf", { opacity: ... })`처럼 별도 트윈을 같은 구간에 겁니다

## reduced-motion
중간 모양 없이 p=0.5에서 원래 모양이 목표 모양으로 바로 바뀝니다(컷). 런타임이 stop 사이를 즉시 건너뛰므로 보통은 완성된 모양만 보입니다. 블러와 3D는 쓰지 않습니다.

## 같이 쓰기 좋은 기법
match-cut(장면 경계에서 대응하는 모양 잇기. 장면 안이면 이 기법), path-drawing(바뀐 구조 위에 흐름 잇기), count-up(구조가 바뀐 뒤 용량이나 수치), highlight-sweep(결론 구절 짚기)
