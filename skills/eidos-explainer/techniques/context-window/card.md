# 컨텍스트 창 (Context Window)

**장면 관계:** 한 장면 안에서 고정 크기 창과 그 창을 지나가는 토큰 흐름을 보여 줄 때 씁니다. 장면 경계의 `via` 값이 아니므로 `s.fx`로 부릅니다.

## 전달하는 의미
**모델은 창 안의 토큰만 본다.** 칸 수가 정해진 창에 새 토큰이 오른쪽에서 들어오면 줄 전체가 한 칸씩 밀리고, 가장 오래된 토큰이 왼쪽 밖으로 나가 흐려집니다. 칸 수는 끝까지 그대로라서 "용량은 고정이고, 넘치면 오래된 것부터 빠진다"가 숫자 없이 읽힙니다. 창 밖으로 나간 토큰은 점선 테두리로 흐리게 남아 무엇을 잊었는지 보여 줍니다.

## 언제 쓰나
- 긴 대화에서 앞에서 한 말(이름, 조건, 지시)을 모델이 놓치는 이유를 설명할 때
- 컨텍스트 길이 한도, 토큰 예산, 최근 문맥만 유지하는 슬라이딩 방식을 보여 줄 때
- 최근 N개만 남기는 버퍼(로그 tail, 링 버퍼, 이동 평균 창)처럼 고정 크기 큐가 핵심일 때

## 피할 때
- 모든 모델과 서비스가 오래된 토큰부터 자동으로 버린다고 단정할 때. 시스템 프롬프트를 고정하거나, 앞부분을 요약해 넣거나, 길이 초과를 오류로 돌려주는 방식도 있으니 캡션에 "이 방식이라면"을 붙이세요
- 실제 창 크기(수만~수십만 토큰)를 그대로 그릴 때. 창은 4~10칸으로 줄여 원리만 보여 주세요. 칸이 많으면 모바일에서 글자가 작아집니다
- 문장이 토큰으로 쪼개지는 과정 자체(token-split), 창 안 문맥으로 다음 토큰을 고르는 과정(next-token)이 주인공일 때

## 사용법
```html
<div class="ctx" id="ctx"><span>내</span><span>이름</span><span>은</span><span>민지</span><span>야.</span><span>안녕!</span><span>배포</span><span>급해</span><span>내</span><span>이름?</span></div>
```
```js
s.fx("context-window", { targets: "#ctx", size: 6, push: 2, steps: 1 }); // 앞 6개가 창을 채운 채 시작, 2개가 들어옴
s.tl.stop("새 토큰 2개가 들어오자 가장 오래된 2개가 밀려났습니다");
s.fx("context-window", { targets: "#ctx", size: 6, push: 2 });           // 같은 트랙에서 이어 나머지를 밀어 넣음
s.tl.stop("답인 ‘민지’는 이미 창 밖에 있습니다");
```
**칩과 칸.** 트랙 요소의 자식 요소 하나가 토큰 칩 하나입니다. 처음 부를 때 앞의 `size`개가 창을 채운 상태로 시작하고, 나머지 칩은 창 오른쪽 밖에 숨어 있다가 차례로 들어옵니다. 칩은 모두 가장 넓은 칩에 맞춘 같은 폭의 칸에 놓입니다(토큰 하나 = 한 칸). 칩은 줄바꿈되지 않으므로 한국어 토큰도 중간에서 끊기지 않습니다. 트랙 폭이 좁으면 창 밖에 남기는 칩 수를 먼저 줄이고(가장 오래된 칩은 반 칸을 지나며 사라짐), 그래도 창이 안 들어갈 때만 글자를 줄입니다. 토큰은 짧게(한글 2자 안팎) 쓰세요.

**이어 부르기.** 같은 트랙에 다시 부르면 앞 호출이 끝난 창에서 이어 밀어 넣습니다. 단계마다 캡션을 직접 쓰려면 `steps: 1`로 부르고 사이에 `s.tl.stop`을 둡니다. `size`는 처음과 같아야 합니다.

칩의 `transform`, `opacity`, 테두리, 배경색은 이 기법이 씁니다. 등장 트윈은 트랙을 감싼 요소에 거세요. 글자 색과 크기는 CSS로 정합니다(트랙의 `font`가 칩에 이어집니다). 반환값의 `frame`(창 테두리 요소)에 라벨을 붙이면 창 위치를 따라갑니다(template.html 참고).

## 파라미터
| 이름 | 기본값 | 설명 |
|---|---|---|
| `targets` | (필수) | 토큰 칩을 자식 요소로 담은 트랙 요소 하나 |
| `size` | (필수) | 창의 칸 수. 칩 수보다 작은 정수 |
| `push` | `1` | 한 단계에 들어오는 토큰 수(1 ~ `size`). 같은 수만큼 가장 오래된 토큰이 밀려납니다 |
| `steps` | 남은 칩을 모두 넣는 단계 수 | 이번 호출의 단계 수. 마지막 단계에는 남은 칩만큼만 들어옵니다 |
| `stopEach` | `false` | `true`면 단계마다 스톱을 붙입니다. 캡션은 "‘배포’ ‘급해’ 들어옴 · ‘내’ ‘이름’ 밀려남"처럼 칩 글자로 만듭니다 |
| `dur` | `0.7` | 한 단계의 시간(초) |
| `at` | 이어서 | 첫 단계 시작 시각 |

반환값: `{ start, end, items: [{ start, end, added, forgotten }], frame }`. `added`는 그 단계에 들어온 칩, `forgotten`은 밀려난 칩 배열입니다. 알 수 없는 옵션, 빠진 `targets`·`size`, 범위를 벗어난 값은 `__eidosErrors`에 넣고 예외를 던집니다.

## 변형
- **한 토큰씩 생성:** `push: 1`로 여러 단계를 이어 붙이면 생성 중인 답이 창을 밀어내는 흐름이 됩니다
- **메시지 단위:** `push: 3`처럼 크게 주면 대화 한 턴이 통째로 들어오고 그만큼 앞이 빠집니다
- **단계별 캡션:** `steps: 1` 호출과 `s.tl.stop`을 번갈아 두면 밀려나는 순간마다 이야기를 붙일 수 있습니다. 빠르게 훑을 때는 `stopEach: true`

## reduced-motion
칩이 미끄러지지 않습니다. 단계가 시작되면 칩의 칸 위치, 불투명도, 테두리, 배경색이 그 단계가 끝난 값으로 바로 바뀌고 중간값을 거치지 않습니다. 런타임이 스톱 사이를 즉시 건너뛰므로 보통은 각 단계가 끝난 창만 보입니다. 블러와 3D는 쓰지 않습니다.

## 같이 쓰기 좋은 기법
token-split(문장을 토큰 칩으로 쪼갠 다음 창에 넣을 때), next-token(창 안 문맥으로 다음 토큰을 고를 때), attention-lines(창 안 토큰끼리만 이어짐을 보일 때), count-up(사용한 토큰 수를 숫자로 함께 보일 때)
