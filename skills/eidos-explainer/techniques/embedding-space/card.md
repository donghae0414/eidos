# 임베딩 공간 (Embedding Space)

**장면 관계:** 한 장면 안에서 단어(짧은 문장) 칩을 평면 위 좌표로 옮겨 "뜻이 비슷하면 가깝다"를 보여 줄 때 씁니다. 장면 경계의 `via` 값이 아니므로 `s.fx`로 부릅니다.

## 전달하는 의미
**뜻이 비슷하면 거리가 가깝다.** 한 줄로 나열된 단어들이 평면 위로 날아가 자리를 잡으면 거리 자체가 의미의 유사성이 됩니다. 칩이 모두 도착하면 같은 무리끼리 색이 들고 이름표가 붙어 군집이 보입니다. 임베딩을 처음 소개할 때, 의미 검색(RAG)의 "가장 가까운 이웃"이 무엇인지 보여 줄 때 그 공간을 눈에 보이게 만드는 기법입니다.

**좌표는 설명용입니다.** `points`의 값은 실제 임베딩 수치가 아니라 작성자가 군집이 보이도록 고른 자리입니다. 두 축도 임의의 투영 축이므로 축 이름이나 눈금에 의미를 두지 마세요. 부제나 캡션에 설명용 좌표임을 밝히세요.

## 언제 쓰나
- 임베딩, 벡터 공간을 처음 소개할 때 (단어 4~10개, 무리 2~3개)
- 의미 검색이 왜 단어가 달라도 같은 뜻을 찾는지 보여 줄 때
- 분류나 클러스터링 결과를 "모인다" 한 동작으로 보여 줄 때

## 피할 때
- 실제 임베딩 값이나 거리를 정확히 보여 줘야 할 때. 이 기법은 좌표를 해석하지 않습니다. 차트 기법(chart-grow, chart-annotate)을 쓰세요
- 단어가 10개를 넘거나 문장이 길 때. 모바일 폭에서 칩이 겹칩니다. 짧은 어절로 줄이거나 두 장면으로 나누세요
- 무리를 평면에서 서로 가까이 둘 때. 무리 테두리가 겹쳐 군집이 흐려집니다. 좌표를 떼어 놓고, 세로 화면용 `portrait` 좌표는 무리를 위아래로 나누세요
- 단어 사이의 연결 자체가 주제일 때(attention-lines), 문장이 토큰으로 쪼개지는 것이 주제일 때(token-split)

## 사용법
```html
<section class="space" id="space" aria-label="고객 문의 여섯 건의 임베딩 공간"></section>
```
```js
s.fx("embedding-space", {
  targets: "#space",
  points: {                                   // 적힌 순서 = 줄 순서 = 출발 순서. 왼쪽으로 갈 칩부터 적어 경로가 엇갈리지 않게
    "비밀번호 재설정": [0.1, 0.15],
    "로그인 안 됨": [0.22, 0.72],
    "계정 잠김": [0.34, 0.42],
    "결제 오류": [0.64, 0.55],
    "환불 요청": [0.78, 0.84],
    "카드 변경": [0.92, 0.3],
  },
  portrait: { "비밀번호 재설정": [0.06, 0.95], "로그인 안 됨": [0.55, 0.7], "계정 잠김": [1, 1],
              "결제 오류": [0.05, 0], "환불 요청": [0.5, 0.12], "카드 변경": [0.95, 0] },  // 세로 화면: 무리를 위아래로
  groups: { "계정": ["비밀번호 재설정", "로그인 안 됨", "계정 잠김"], "결제": ["결제 오류", "환불 요청", "카드 변경"] },
});
s.tl.stop("임베딩 모델이 문장을 좌표로 옮기면 뜻이 비슷한 문의끼리 모입니다");
```
**플롯 박스.** `targets`는 크기가 있는 요소 하나입니다(`position`이 static이면 기법이 relative로 바꿉니다). 기법이 그 안에 단어 칩(`span.eidos-emb-word`), 축 선(`svg.eidos-emb-axes`), 무리 테두리(`div.eidos-emb-group`)를 만듭니다. 칩은 박스 윗부분에 가운데 정렬된 한 줄로 놓였다가 그 아래 평면으로 날아갑니다. 좁은 화면에서 한 줄에 다 들어가지 않으면 줄이 늘어나는데, 처음 적은 칩들이 평면 바로 윗줄에, 나중 칩들이 그 위 줄에 놓입니다. 먼저 적은 칩부터 출발하므로 윗줄 칩이 내려올 때 아랫줄은 이미 비어 있습니다. 좌표 `[x, y]`는 평면 안의 0~1 비율(왼쪽 위가 `[0, 0]`)이며, 칩 크기와 테두리 여백만큼 안쪽으로 들여 계산하므로 0이나 1을 줘도 칩이 박스 밖으로 나가지 않고, 이동 중에도 박스 안에 머뭅니다. 칩 글자 크기는 박스의 `font-size`를 따릅니다. 축 선은 이동이 시작될 때 나타납니다.

**겹치지 않게 적는 법.** 이웃한 두 칩이 서로를 향해 움직이면 출발 직후에 겹칩니다. 왼쪽으로 갈 칩들을 먼저, 오른쪽으로 갈 칩들을 나중에 적고, 같은 방향으로 가는 이웃은 뒤에 적은 칩이 더 멀리 가게 두세요(출발이 늦은 칩이 따라잡히지 않습니다). 세로 화면 좌표도 같은 규칙으로, 먼저 적은 줄의 칩은 먼 띠로, 나중 줄의 칩은 가까운 띠로 보내면 서로의 자리를 지나가지 않습니다.

**무리.** `groups`는 `{ 이름: [단어, ...] }`이며 적힌 순서대로 `--eidos-cat-1~5`를 받습니다. 칩이 모두 도착하면 무리의 칩이 그 색으로 물들고, 칩들을 감싸는 옅은 테두리와 이름표가 함께 나타납니다. 무리에 없는 단어는 기본색 그대로입니다. 무리 테두리는 칩들의 경계 상자이므로 같은 무리 단어를 한쪽에 모아 두세요.

## 파라미터
| 이름 | 기본값 | 설명 |
|---|---|---|
| `targets` | (필수) | 플롯 박스 요소 하나 |
| `points` | (필수) | `{ 단어: [x, y] }`. 2~10개. x, y는 0~1 비율. 적힌 순서가 줄 순서이자 출발 순서 |
| `portrait` | 없음 | 세로 화면(`max-aspect-ratio: 1/1`, 레이아웃 때마다 다시 판정)에서 쓸 좌표. `points`와 같은 꼴이며 적은 단어만 덮어씁니다 |
| `groups` | 없음 | `{ 이름: [단어, ...] }`. 최대 5개, 단어는 한 무리에만 |
| `dur` | `0.9` | 칩 하나의 이동 시간(초) |
| `each` | `0.09` | 칩 사이 출발 간격(초) |
| `arc` | `20` | 이동 경로의 휨(px). `tl.tween`의 `arc`와 같은 규칙: 양수는 진행 방향의 왼쪽 법선 쪽으로 휘고(오른쪽 아래로 가는 칩은 아래로 처짐), 음수는 반대, `0`이면 직선. 휘어도 칩은 박스 밖으로 나가지 않습니다 |
| `at` | 이어서 | 시작 시각 |

반환값: `{ start, end, items: [{ el, text, start, end, group }], groups: [{ label, el, items }] }`. `el`은 칩 span, `groups[].el`은 무리 테두리, `end`는 테두리와 색까지 다 나타난 시각입니다. 모르는 옵션, 빠진 `points`, 범위 밖 좌표, `points`에 없는 단어를 가리키는 `portrait`/`groups`는 빌드 때 오류로 멈춥니다.

## 변형
- **무리 없이:** `groups`를 빼면 칩만 이동합니다. 거리 하나만 말하고 싶을 때
- **한 무리만 강조:** 강조할 무리를 `groups`의 첫 번째에 두면 `--eidos-cat-1`(강조색)을 받습니다. 그 장면에서 다른 강조색은 쓰지 마세요
- **직선 이동:** `arc: 0`. 칩이 적고 경로가 짧을 때
- **하나씩 천천히:** `each: 0.3`이면 단어가 하나씩 자리를 찾아가는 리듬이 됩니다

## reduced-motion
칩이 날아가지 않습니다. 줄에 놓인 칩이 자기 차례에 흐려지는 동안 같은 칩이 목표 자리에서 나타납니다(불투명도만 바뀌고 위치는 처음부터 고정). 축 선과 무리 테두리도 불투명도로만 나타나며, 무리 색은 테두리가 나타나기 시작할 때 중간값 없이 바로 바뀝니다. 런타임이 stop 사이를 즉시 건너뛰므로 보통은 완성된 평면만 보입니다. 블러와 3D는 쓰지 않습니다.
