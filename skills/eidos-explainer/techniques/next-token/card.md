# 다음 토큰 고르기 (Next-token Pick)

**장면 관계:** 한 장면 안에서 언어 모델이 토큰 하나를 고르는 순간을 보여 줄 때 씁니다. 장면 경계의 `via` 값이 아니므로 `s.fx`로 부릅니다.

## 전달하는 의미
**모델은 다음 자리에 올 후보마다 확률을 매기고, 그중 하나를 골라 문장에 붙인다.** 문장 끝 빈칸 아래에서 후보 토큰과 확률 막대가 자라고, 고른 후보가 강조색으로 바뀌며 나머지는 흐려진 뒤, 고른 단어가 후보 줄에서 떠올라 호를 그리며 빈칸에 들어가 문장을 잇습니다(후보 줄의 단어는 토큰이 자리 잡으면 다시 보입니다). 이어 부르면 "붙이고 다시 예측한다"는 자기회귀 생성의 반복이 됩니다. 화면의 확률은 설명용 예시입니다. 실제 모델 출력이 아니면 화면 주석이나 캡션에 그렇게 밝힙니다.

## 언제 쓰나
- LLM이 답을 한 번에 쓰지 않고 토큰을 하나씩 이어 붙인다는 원리를 설명할 때
- 그리디 디코딩과 샘플링(temperature, top-p)의 차이를 보여 줄 때. `pick`으로 1위가 아닌 후보를 고릅니다
- 프롬프트나 앞 문맥이 바뀌면 다음 토큰의 확률도 바뀐다는 것을 장면마다 비교할 때

## 피할 때
- 예시 확률을 실제 측정값처럼 보이게 할 때. 예시 값이면 "확률은 설명을 위한 예시" 주석을 화면에 둡니다
- 항상 1위만 뽑힌다고 일반화할 때. 샘플링을 다루면 1위가 아닌 후보를 고르는 stop을 하나 둡니다
- 후보가 7개 이상일 때. 상위 2~6개만 적으면 나머지 확률은 기법이 "그 밖의 토큰 N%" 줄로 합쳐 보여 줍니다
- 문장이 토큰으로 쪼개지는 경계 자체가 주제일 때(token-split), 답이 흘러나오는 느낌만 필요할 때(text-scramble `mode: "type"`)
- 빈칸이 문단 중간에 있을 때. 후보 목록이 문장 요소 바로 아래에 들어가므로 빈칸은 문장 끝에 둡니다

## 사용법
```html
<p class="answer">원인은 DB 커넥션 풀이 <span id="t1"></span> <span id="t2"></span>.</p>
<p class="note">확률은 설명을 위한 예시입니다.</p>
```
```js
s.fx("next-token", {
  targets: "#t1",
  candidates: [
    { text: "고갈되었기", p: 0.48 },
    { text: "부족했기", p: 0.27 },
    { text: "막혔기", p: 0.12 },
  ],
});                                    // 1위 '고갈되었기'가 빈칸으로
s.tl.stop("후보마다 확률을 매기고 가장 높은 '고갈되었기'를 붙입니다");
s.fx("next-token", {
  targets: "#t2",
  candidates: [{ text: "때문입니다", p: 0.71 }, { text: "때문이에요", p: 0.19 }],
  pick: 1,                             // 샘플링: 2위가 뽑힘
});
s.tl.stop("붙인 토큰까지 읽고 다시 고릅니다. 샘플링이면 2위도 뽑힙니다");
```
**빈칸.** `targets`는 문장 끝의 빈 인라인 요소 하나입니다. 기법이 고를 토큰을 그 안에 보이지 않게 미리 넣고 밑줄을 그으므로 빈칸 너비가 들어올 토큰 너비와 같습니다. 그래서 토큰이 들어와도 문장이 다시 줄바꿈되지 않습니다. 들어온 토큰은 문장과 같은 글꼴에 강조색입니다.

**후보 목록.** 기법이 빈칸을 품은 문장 요소(`<p>` 같은 블록) 바로 다음에 후보 칸(`.eidos-nt-room`)을 넣고, 그 안에 후보 단어, 확률 막대, 백분율을 한 줄씩 그립니다. 후보 칸은 처음부터 자리를 차지하므로 후보가 나타날 때 아래 내용이 밀리지 않습니다. 목록은 빈칸의 가로 위치 아래에 놓이고, 화면이 좁으면 문장 폭 안으로 당겨집니다. 후보 단어는 빈칸 문장과 같은 글꼴과 굵기를 씁니다. 후보는 적은 순서대로 위에서 아래로 놓이니 확률이 높은 순서로 적으세요.

**이어 부르기.** 다음 `next-token` 호출이 시작되면 앞 호출의 후보 목록이 사라지고 앞 토큰은 강조색을 내려놓습니다. 같은 문장의 빈칸들은 후보 칸 하나를 함께 씁니다.

## 파라미터
| 이름 | 기본값 | 설명 |
|---|---|---|
| `targets` | (필수) | 문장 끝의 빈 인라인 요소 하나(빈칸) |
| `candidates` | (필수) | `[{ text, p }]` 2~6개. `text`는 후보 토큰, `p`는 0~1 확률이고 합은 1을 넘을 수 없습니다 |
| `pick` | 확률이 가장 높은 후보 | 고를 후보 번호(0부터). 1위가 아닌 번호면 샘플링 장면이 됩니다 |
| `dur` | `2.4` | 전체 시간(초). 후보 등장과 막대 성장에 약 60%, 선택 강조에 10%, 빈칸으로 날아가는 데 30%를 씁니다. 이어 부를 때는 앞 목록이 사라지는 시간(12%)이 앞에 붙습니다 |
| `at` | 이어서 | 시작 시각 |

반환값: `{ start, end, items, token, panel }`. `items`는 후보마다 `{ el, bar, p, picked, start, end }`이고 `el`은 후보 단어입니다. `token`은 빈칸에 들어간 토큰 요소, `panel`은 후보 목록 요소입니다.

## 변형
- **그리디:** `pick`을 생략하면 확률이 가장 높은 후보가 들어갑니다
- **샘플링:** `pick: 1`처럼 1위가 아닌 후보를 고르고, 캡션에 "샘플링이면 낮은 확률도 뽑힌다"를 적습니다
- **자기회귀 반복:** 빈칸을 여러 개 두고 차례로 부르면 고른 토큰을 붙여 다시 예측하는 루프가 됩니다. 두세 번이면 충분합니다
- **문맥 비교:** 같은 빈칸을 다른 프롬프트로 두 화면에 놓고(split-screen) 후보 확률이 어떻게 달라지는지 보여 줍니다

## reduced-motion
후보 단어와 막대가 이동 없이 나타나고(막대는 처음부터 최종 길이, 불투명도만 0 → 1), 고른 토큰은 날아가지 않고 빈칸 자리에서 바로 나타납니다. 강조색은 서서히 섞이지 않고 한 번에 바뀌고, 나머지 후보는 불투명도만 낮아집니다. 런타임이 stop 사이를 즉시 건너뛰므로 보통은 완성된 상태만 보입니다. 블러와 3D는 쓰지 않습니다.

## 같이 쓰기 좋은 기법
