# 의도별 기법 레시피

질문과 맞는 레시피에서 출발합니다. 기법을 전부 넣는 것이 목표는 아닙니다. 각 움직임이 설명할 개념을 먼저 정하고, 내용에 맞게 줄이거나 길이를 바꿉니다. 구조는 [decision-table.md](decision-table.md), 장면 경계는 [transitions.md](transitions.md)에서 별도로 고릅니다. 아래 기법은 모두 장면 안에서 s.fx로 부르며, 장면 경계의 via 값이 아닙니다.

## 공통 규칙

- **시각은 초 단위입니다.** 표의 at은 한 장면이 0초에서 시작할 때의 절대 시각입니다. 앞 장면이 있으면 그 장면의 시작 시각을 더합니다. dur은 기법에 주는 옵션이며 전체 길이와 다를 수 있습니다. 각 행 끝에서 s.tl.stop을 호출합니다. 자동 stop을 만드는 기법은 표에 따로 적었습니다.
- **반환값의 end를 기준으로 잇습니다.** 대상 수, each, 문장 길이가 달라지면 다음 at도 다시 계산합니다. stop은 타임라인 끝에 붙으므로 별도 대기 시간을 더하지 않습니다.
- **카드가 옵션의 기준입니다.** 각 기법의 card.md에서 파라미터를 읽습니다. dur이 없는 기법에 dur을 넣지 않습니다. 모든 DOM과 기법 호출은 s.start() 전에 만듭니다.
- **초점은 하나입니다.** 다음 강조가 시작되기 전에 앞 강조를 거둡니다. 움직임은 stop 사이에서 끝나고, stop에서는 반복 펄스나 커서 깜빡임이 없습니다. [motion-principles.md](motion-principles.md) 3·4·8절을 따릅니다.

## 1. LLM 원리

**언제:** 문장을 처리 단위로 나누고, 앞 문맥을 참조해 다음 토큰 하나를 고르는 과정을 설명할 때입니다.

**순서:** `token-split` → `attention-lines` → `next-token`

| 순서 | 기법과 옵션 | 끝과 stop |
| --- | --- | --- |
| 1 | token-split: targets는 글자만 있는 문장 하나. `tokens: ["AI는", " 다음", " 말을"]`, `gap: 8`, `at: 0`, `dur: 0.6`, `each: 0.04`. 번호는 생략 | 0.68초. “문장을 세 토큰으로 나눠 읽습니다” |
| 2 | attention-lines: targets는 앞 호출 items의 el 배열. `from: 2`, `weights: [0.7, 0.3, 0]`, `at: 0.68`, `dur: 0.8`, `each: 0.12` | 질의 테두리 0.3초 + 호 시차 0.12초 + 그리기 0.8초 + 최종 강조 0.35초 = 1.57초. 끝 2.25초. “앞 토큰을 서로 다른 비중으로 참조합니다” |
| 3 | 앞 호 SVG의 opacity를 `at: 2.25`, `dur: 0.2`로 1에서 0으로 거둡니다. next-token: 별도 문장 끝 빈 span을 targets로, `candidates: [{ text: "고른다", p: 0.7 }, { text: "잇는다", p: 0.2 }]`, `at: 2.45`, `dur: 2.4` | 4.85초. “다음 토큰을 골라 붙이고 다시 예측합니다” |

**배치와 연결:** token-split 대상에는 빈칸 span을 넣지 않습니다. 입력 문장과 다음 토큰용 문장을 따로 두고, 후자는 앞 호를 거두는 0.2초 동안 opacity로 공개합니다. 후보 목록이 처음부터 차지하는 공간도 예약합니다. 어텐션 줄은 모바일에서도 한 줄이어야 하고, 위에는 호 높이, 아래에는 숫자 한 줄을 비웁니다.

**분리가 끝난 뒤 선을 그립니다.** attention-lines는 onLayout에서 transform 전 레이아웃 위치를 잽니다. token-split은 최종 간격을 레이아웃 margin으로 미리 확보하고, 분리 중에만 transform으로 붙은 상태를 만듭니다. 따라서 attention-lines의 at은 token-split이 반환한 end 이상이어야 합니다. 두 기법을 동시에 시작하면 선 끝이 움직이는 토큰과 어긋납니다. ids를 추가하면 번호 페이드까지 end가 늘어나므로 0.68초를 그대로 쓰지 않습니다.

**원칙:** [motion-principles.md](motion-principles.md) 4절의 포즈 투 포즈로 분리·참조·선택의 결과를 각각 멈춥니다. 3절의 무대 연출에 따라 호의 강조를 거둔 뒤 후보를 강조합니다. 7절의 호 이동은 next-token 내부의 후보→빈칸 이동이 맡습니다.

**피할 때:** 토큰 경계·가중치·확률을 실제 측정값으로 오해하게 만드는 것. 화면에 “설명용 예시”를 적습니다. 어텐션 비중을 다음 토큰 확률과 같은 값으로 설명하지 않고, 최고 확률 선택은 그리디 예시임을 밝힙니다. 긴 문장, 여러 줄 어텐션, 분리 중인 토큰의 참조 선은 피합니다.

## 2. 전후 비교

**언제:** 같은 조건에서 개선 전후의 수치와 바뀐 문구를 함께 설명할 때입니다.

**순서:** `split-screen` → `count-up` → `strikethrough-replace` 또는 `highlight-sweep`

| 순서 | 기법과 옵션 | 끝과 stop |
| --- | --- | --- |
| 1 | split-screen: left/right는 전후 두 판, divider는 구분선. `at: 0`, `dur: 0.8`, steps는 생략 | 0.8초. “같은 요청의 개선 전후를 나란히 봅니다” |
| 2 | count-up: 후 쪽 숫자 하나, `from: 120`, `to: 30`, `unit: "ms"`, `reserve: true`, `at: 0.8`, `dur: 1.2` | 2초. “같은 조건에서 지연이 120ms에서 30ms로 줄었습니다” |
| 3 | 문구 정정이면 strikethrough-replace: targets는 옛 구절, to는 바로 다음 새 구절. `place: "below"`, `at: 2`, `dur: 0.45`, `gap: 0.15` | 새 문구 등장 0.3초까지 합해 끝 2.9초. “전체 조회를 버리고 필요한 행만 읽습니다” |
| 3 대안 | 정정이 아니라 결론을 짚으면 highlight-sweep: 결론 구절 하나, `at: 2`, `dur: 0.55` | 2.55초. “핵심 차이는 읽는 행 수입니다” |

**원칙:** [motion-principles.md](motion-principles.md) 10절의 과장은 실제 전후 차이에만 씁니다. 숫자는 같은 단위·조건을 유지하고, 3절에 따라 숫자와 새 문구에 강조색을 동시에 주지 않습니다.

**피할 때:** 서로 다른 부하·단위의 수치를 나란히 비교하는 것, 세 대상을 분할하는 것, 두 마지막 기법을 모두 넣어 같은 결론을 반복하는 것. 모바일에서는 두 판을 위아래로 놓고 대응되는 항목 순서를 지킵니다.

## 3. 핵심 문장/인용

**언제:** 짧은 주장이나 인용문을 읽힌 뒤 핵심어 하나에 강세를 남길 때입니다.

**순서:** `mask-reveal` → `highlight-sweep` → `kinetic-type` pulse

| 순서 | 기법과 옵션 | 끝과 stop |
| --- | --- | --- |
| 1 | mask-reveal: 직접 나눈 두 줄을 targets로, `at: 0`, `dur: 0.8`, `each: 0.14` | 0.94초. “먼저 결론 문장 전체를 읽습니다” |
| 2 | highlight-sweep: 한 줄 안 핵심 구절 하나, `at: 0.94`, `dur: 0.55` | 1.49초. “기억할 것은 이 구절입니다” |
| 3 | kinetic-type: 앞 구절 안의 한 단어만 targets로, `move: "pulse"`, `scale: 1.08`, `at: 1.49`, `dur: 0.5` | 1.99초. “이 단어가 주장의 핵심입니다” |

**원칙:** [motion-principles.md](motion-principles.md) 8절의 보조 동작은 같은 주장에만 붙입니다. 9절에 따라 읽을 수 있는 길이를 확보하고, pulse는 한 번 커졌다 돌아온 뒤 멈춥니다. reduced-motion에서는 pulse가 생략되므로 앞 하이라이트와 문장만으로도 결론이 전달되어야 합니다.

**피할 때:** 본문 문단 전체를 움직이는 것, 펄스를 반복하는 것, 긴 어절이 모바일 폭을 넘는 것. 인용의 출처는 별도로 표기하고 교재 예문을 실제 발언처럼 쓰지 않습니다. 형광펜은 글자 뒤 별도 mark에 있으므로 pulse 대상의 transform과 겹치지 않게 둡니다.

## 4. 데이터 결론 먼저

**언제:** 요약 수치를 먼저 제시하고, 같은 지표의 분포나 추세와 해석으로 근거를 보여 줄 때입니다.

**순서:** `count-up` → `chart-grow` → `chart-annotate`

| 순서 | 기법과 옵션 | 끝과 stop |
| --- | --- | --- |
| 1 | count-up: 요약 숫자 하나, `from: 0`, `to: 24`, `unit: "회"`, `reserve: true`, `at: 0`, `dur: 1.2` | 1.2초. “이번 달 배포는 24회입니다” |
| 2 | chart-grow: 빈 el 컨테이너, `kind: "bar"`, `categories: ["1월", "2월", "3월"]`, `values: [12, 18, 24]`, `max: 30`, `unit: "회"`, `at: 1.2`, `dur: 1.2`, `each: 0.12` | 막대 셋의 시차를 합해 끝 2.64초. “최근 세 달 배포 횟수가 늘었습니다” |
| 3 | chart-annotate: 앞 호출 points[2]를 target으로, 별도 slot 예약, `text: "3월 24회: 세 달 중 최다"`, `at: 2.64`, `dur: 0.9` | 3.54초. “3월이 세 달 중 가장 많습니다” |

**원칙:** [motion-principles.md](motion-principles.md) 10절처럼 축을 왜곡하지 않고 주석으로 차이를 설명합니다. 3절에 따라 요약 숫자는 기본 전경색으로 두고 최종 초점은 주석 하나로 옮깁니다.

**피할 때:** 서로 다른 지표를 숫자와 차트에 쓰는 것, 0 기준선을 숨기는 것, 시간적 일치만으로 원인을 단정하는 것. 음수·누적 계열은 이 chart-grow 카드 범위 밖입니다.

## 5. 구조 훑기

**언제:** 익숙한 세부에서 전체 구조로 물러난 뒤, 이미 보이는 구성 요소를 훑고 핵심 부분 안으로 들어갈 때입니다.

**순서:** `establishing-shot` → `focus-handoff` → `zoom-in`

| 순서 | 기법과 옵션 | 끝과 stop |
| --- | --- | --- |
| 1 | establishing-shot: from은 익숙한 노드, context는 주변 지도. 시작 at=0(현재 타임라인 끝), `introDur: 0.6`. 일반 dur 대신 introDur을 씁니다 | 0.6초. “이 서버 하나에서 출발합니다” |
| 1 이어서 | 반환값 shot.pullBack 호출. at=0.6(현재 끝), `dur: 1.4`, `target: "world"`. labels는 생략해 추가 시차 없음 | 2초. “서버는 이 전체 구조의 한 부분입니다” |
| 2 | focus-handoff: 보이는 노드 셋, `order: [0, 1, 2]`, `labels: ["입구에서 요청을 받습니다", "서비스에서 처리합니다", "DB에 상태를 남깁니다"]`, `at: 2`, `dur: 0.35`, `stopEach: true` | 자동 stop 2.35·2.70·3.05초. 수동 stop을 중복 추가하지 않습니다 |
| 3 | zoom-in: 마지막에 켜진 DB를 target으로, `dur: 1.4`. at=3.05(현재 끝)에서 호출 | 4.45초. “상태를 남기는 DB 내부를 자세히 봅니다” |

**원칙:** [motion-principles.md](motion-principles.md) 3절의 전체 지도 예외 다음에 초점을 하나씩 넘깁니다. 6절의 카메라 이징과 9절의 이동 길이를 따릅니다. 카메라 카드의 현재 끝에서 이어지는 호출을 사용하므로 지원하지 않는 일반 dur을 첫 establishing-shot에 넣지 않습니다.

**피할 때:** 항목이 아직 보이지 않는데 초점부터 넘기는 것, 여섯 항목 넘게 순회하는 것, 공간적으로 이어지지 않는 대상 사이를 줌으로 잇는 것. 마지막 노드의 1.02배 강조는 그대로 유지해도 되며, 전체 복원이 필요하면 restore의 end 이후에 카메라 이동을 시작하고 다음 at을 다시 계산합니다.

## 6. 제품/프롬프트 흐름

**언제:** 사람이 넣은 요청이 어떤 주체를 거쳐 처리되는지 보이고, 결과 UI의 중요한 영역을 짚을 때입니다.

**순서:** `typing-caret` → `sequence-message` → `spotlight`

| 순서 | 기법과 옵션 | 끝과 stop |
| --- | --- | --- |
| 1 | typing-caret: 입력창의 글자 “요약해 줘”, `cps: 18`, `jitter: 0`, `seed: 1`, `at: 0`. dur 옵션은 없습니다 | 다섯 글자 간격(공백 1.6배) + 마지막 한 박자 = 6.6/18초, 약 0.367초. 정확한 끝은 반환값 r.end. “요약 요청을 입력했습니다” |
| 2 | 입력 커서를 r.end부터 opacity 1→0, `dur: 0.2`로 끕니다. sequence-message는 el 컨테이너와 사용자·앱·모델의 actors, 요청·응답 두 messages를 지정. `at: r.end + 0.2`, `dur: 0.7`, `perStop: true` | 행위자 등장 시간을 포함한 끝은 반환값 q.end로 받습니다. 각 메시지의 note를 캡션으로 자동 stop 두 개. 수동 stop을 중복 추가하지 않습니다 |
| 3 | spotlight: 이미 보이는 응답 카드 하나, `pad: 12`, `dim: 0.55`, `at: q.end`, `dur: 0.5` | q.end + 0.5초. “응답에서 읽을 곳은 이 요약 영역입니다” |

**원칙:** [motion-principles.md](motion-principles.md) 4절처럼 입력 완료·전달·결과 읽기의 포즈를 정합니다. 3절에 따라 커서를 끈 뒤 초점을 응답으로 넘기고, 8절에 따라 요청과 무관한 클릭 파문이나 장식을 더하지 않습니다.

**피할 때:** 사람이 치는 입력을 모델 응답처럼 표현하는 것, 입력이 끝나기 전에 요청 화살표를 보내는 것, 길어진 프롬프트에도 고정 0.367초를 쓰는 것. 실제 응답 카드는 q.end까지 공개되어 있어야 하며, spotlight와 카메라 이동을 겹치지 않습니다. 가변 입력 길이와 기본 jitter를 쓸 때는 반드시 r.end를 따릅니다.
