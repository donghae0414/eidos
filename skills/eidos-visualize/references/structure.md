# 구조 고르기

스토리보드 첫 줄은 구조입니다. 구조가 정해져야 장면 수, 전환, 탐색 방식이 따라옵니다.

```md
structure: hub-and-spoke (hub: map; spokes: scheduler, kv-cache, batching)
```

## 세 가지 구조

| 구조 | 언제 | 모양 |
| --- | --- | --- |
| `single-flow` | 이야기가 한 줄로 이어질 때. 흐름, 절차, 상태 변화 | 장면 1 → 2 → 3 |
| `layered-chapters` | 큰 단계 몇 개가 있고, 단계마다 안을 들여다볼 때 | 장 1(장면 몇 개) → 장 2 → 장 3, 장 사이는 `dip-to-color` 같은 장 전환 |
| `hub-and-spoke` | 여러 개념이 한 지도에 묶여 있고, 순서보다 관계가 중요할 때. 시스템 동역학, 구성 요소 둘러보기 | 지도 → 갈래 A → 지도 → 갈래 B → 지도 → 마무리 |

고르는 질문은 하나입니다. "독자가 앞에서 본 걸 계속 지도처럼 들고 있어야 하나?" 그렇다면 hub-and-spoke, 단계가 뚜렷하면 layered-chapters, 아니면 single-flow입니다.

## 분량 가이드

- 장면 하나에 스톱 3~7개를 권합니다.
- 장면 하나에 기법 2~5개를 권합니다.

둘 다 상한이 아니라 출발점입니다. 내용이 더 필요하면 넘겨도 됩니다. 다만 스톱마다 스토리보드로 추적할 수 있는 움직임이 있어야 합니다(principles.md).

## 허브 앤 스포크를 쓸 때

허브 불변식은 하나만 기억하면 됩니다. **갈래에서 돌아오면 지도는 처음 모습 그대로여야 합니다.**

- 갈래 안에서 바꾼 색, 크기, 위치는 복귀 구간(`s.back`) 안에서 모두 되돌립니다.
- 허브 상태 스톱은 여러 개입니다. 처음 도착한 `#hub.0`, 갈래마다 하나씩인 `#hub.ret-A`, `#hub.ret-B`. 화면은 같고 다음 목적지만 다릅니다.
- 그래서 지도에 "어디를 봤는지" 표시를 남기고 싶어도 남기지 않습니다. 그런 표시는 HUD 브레드크럼이 맡습니다.
- 갈래 들어가기와 돌아오기는 보통 `camera`입니다. 지도 속 부분으로 들어가는 관계이기 때문입니다(transitions.md 표 A).
- 독자는 노드를 클릭하거나 숫자 키로 갈래에 들어가고, Esc로 나옵니다. 자동 재생은 허브 → A → 허브 → B 순서를 그대로 따라갑니다.
