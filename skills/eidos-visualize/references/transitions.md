# 장면 전환 고르기

전환은 두 장면이 서로 어떤 관계인지 보여 주는 문장입니다. 새로워 보여서 고르는 게 아니라, 두 장면의 관계를 보고 고릅니다.

이 문서에는 표가 두 개 있습니다. 둘은 호출 방식이 다르니 섞지 마세요.

- **표 A**는 장면 경계에 쓰는 `via` 값입니다. `s.scene`, `s.spoke`, `s.back`의 `via` 옵션에만 들어갑니다.
- **표 B**는 장면 안에서 관계를 보여 주는 기법입니다. `via`에 넣으면 런타임이 예외를 던집니다. `s.fx`로 부릅니다.

## 표 A. 장면 경계 via

호출 형태:

```js
s.scene("decode", { el: "#decode", via: "jump-cut", reason: "같은 그림의 나중 상태" });
s.spoke("A", { hub: "hub", from: "#node-a", via: "camera", reason: "지도 속 부분으로 들어감" });
s.back({ via: "camera" });
```

여기 적힌 값은 `kind: transition` 카드의 id와 내장값 `camera`, `cut`뿐입니다. 스토리보드 경계 표의 `via` 칸도 이 표에서만 고릅니다.

| 두 장면의 관계 | via | 메모 |
| --- | --- | --- |
| 같은 그림의 나중 상태 | `jump-cut` | 배치는 그대로, 상태만 건너뜁니다 |
| 한 부분 안으로 들어감 | `camera` | `camera.to(el)`로 그 요소를 확대합니다 |
| 화면이나 창 안으로 들어감 (UI) | `screen-dive` | 기기나 창의 테두리가 다음 장면이 됩니다 |
| 단어가 문이 되어 들어감 | `zoom-through` | 큰 글자를 통과해 다음 장면으로 갑니다 |
| 다시 전체 맥락으로 나옴 | `camera` | `back()`이 카메라를 뒤로 뺍니다 |
| 나란한 다른 개념으로 옆 이동 | `whip-pan` | 빠른 옆 이동, 같은 층위라는 신호입니다 |
| 나란한 다른 개념으로 교체 | `wipe` | 경계선이 지나가며 바뀝니다 |
| 모양이 서로 대응함 | `match-cut` | 앞 장면의 모양이 뒤 장면의 모양으로 이어집니다 |
| 출발한 요소가 중요함 | `iris` | 그 요소를 중심으로 열리고 닫힙니다 |
| 장(chapter)이 바뀜 | `dip-to-color` | 한 색으로 잠깐 덮었다가 엽니다 |
| 대비, 반전, 폭로 | `smash-cut` | 예고 없이 정반대 장면으로 자릅니다 |
| 같은 데이터를 다시 묶음 | `pixel-dissolve` | 칸 단위로 흩어졌다가 새 묶음으로 모입니다 |
| 중립적 이동, 시간이 흐름 | `cross-dissolve` | 기본값처럼 쓰지 말고 관계가 중립일 때만 씁니다 |
| 급하게 끊음 | `cut` | 0초 전환입니다 |

## 표 B. 장면 안에서 쓰는 관계 기법 (via 아님, s.fx로 호출)

호출 형태:

```js
s.fx("shape-morph", { from: "#queue", to: "#ring", at: 2, dur: 1.2 });
```

모두 `kind: technique`입니다. 관계를 표현하지만 장면을 바꾸지 않고 한 장면 안에서 움직입니다.

| 장면 안의 관계 | 기법 | 메모 |
| --- | --- | --- |
| 한 장면 안에서 모양이 바뀜 | `shape-morph` | 같은 대상이 다른 구조가 된다는 뜻입니다 |
| 세부에서 맥락으로 물러남 | `crane-up` | 장면은 그대로, 카메라만 위로 빠집니다 |
| 동시에 일어나는 두 흐름 | `cross-cutting` | 한 장면 안의 두 칸을 번갈아 보여 줍니다 |
| 잠깐 옆길로 갔다가 돌아옴 | `cutaway` | `s.spoke`와 `s.back` 위에 얹은 짧은 우회입니다 |
| 한 부분을 가까이 봄 | `zoom-in` | 장면을 넘기지 않는 확대입니다 |
| 둘을 나란히 비교함 | `split-screen` | 한 화면을 나눠 동시에 보여 줍니다 |

## 규칙

1. **관계로 고릅니다.** 새로워 보여서, 화려해서 고르지 않습니다. 스토리보드 경계 표의 `reason`에 관계를 한 문장으로 적고, 같은 문장을 `s.scene`의 `reason`에 옮깁니다.
2. **같은 via는 연속 3번까지입니다.** 네 번째부터는 리듬이 죽습니다. cross-dissolve 카드의 "연속 4번" 경고와 같은 이야기입니다. 중간 하나를 `cut`이나 관계에 맞는 다른 값으로 바꿉니다.
3. **강한 전환은 아껴 씁니다.** `smash-cut`, `pixel-dissolve`, `iris`는 한 작품에서 각각 2번까지입니다.
4. **J컷과 L컷은 via가 아닙니다.** 캡션을 먼저 바꾸려면 `s.scene(id, {lead})`, 이전 캡션을 더 남기려면 `{trail}`을 씁니다. 화면 상태와 스톱 시각은 그대로입니다.
5. **표 B를 via에 넣지 않습니다.** 예외가 나고 `__eidosErrors`에 기록됩니다.

> 참고: 이 문서를 쓰는 시점에 `wipe`, `iris`, `jump-cut`, `smash-cut`, `dip-to-color`, `whip-pan`, `screen-dive`, `zoom-through`, `pixel-dissolve`, `crane-up`, `cross-cutting`, `cutaway`, `shape-morph` 카드는 아직 만드는 중입니다. 각 id의 kind는 계획(todo 6, 9~14)과 docs/runtime-api.md (k)를 따랐습니다.
