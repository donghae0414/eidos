# 컨트롤 쓰기

컨트롤은 독자가 값을 바꿔 보며 관계를 손으로 확인하게 해 줍니다. 모든 시각화에 필요한 건 아닙니다.

## 언제 도움이 되나

- **trade-off.** 한쪽을 올리면 다른 쪽이 내려가는 관계. 배치 크기와 지연, 캐시 크기와 적중률.
- **what-if.** "이 값이 두 배면?"을 독자가 직접 묻고 싶은 경우.

흐름이나 절차처럼 값이 없는 설명에는 컨트롤을 두지 않습니다. 스토리보드에 `controls: none`이라고 적습니다.

## 규칙

1. **값만 바꿉니다.** 컨트롤은 스톱 시각, 장면 구간, DOM 구조를 바꾸지 않습니다. 필요한 노드는 `start()` 전에 모두 만들고, 컨트롤은 opacity, scale, 속성만 바꿉니다.
2. **라벨에 단위를 붙입니다.** `"배치 크기 (요청 수)"`, `"지연 (ms)"`처럼 씁니다.
3. **보일 때만 보입니다.** 그 값이 의미 있는 구간에만 `when`으로 범위를 줍니다. 스톱 범위 `[stopA, stopB]`(스톱 id나 번호)나 장면 id를 씁니다. `when`이 없으면 항상 보입니다. 표시 여부는 `when` 하나로만 정하고, `layout`이나 `sticky`와는 상관없습니다.
4. **화면은 params의 결정적 함수입니다.** `s.onParams`에서 params만 보고 다시 계산합니다. 같은 값이면 언제나 같은 화면이어야 합니다. 난수, 현재 시각, 이전 상태 누적은 쓰지 않습니다.
5. **화면이 바뀌어야 합니다.** 값을 바꿔도 아무것도 안 바뀌는 컨트롤은 QA에서 실패입니다.
6. **가짜 정밀도를 피합니다.** 실제 측정이 아닌 모델이면 그렇다고 적습니다. `"처리량 (상대값, 단순 모델)"`처럼 라벨에 밝히고, 소수점 숫자를 늘어놓지 않습니다.

## 예

```js
const batch = s.control("batch", {
  type: "range", min: 1, max: 8, step: 1, value: 4,
  label: "배치 크기 (요청 수)", when: "batching",
});
s.onParams(({ batch }) => {
  // 블록 줄 수와 처리량 막대를 batch만으로 계산
});
```

스토리보드 control 표에는 화면에서 무엇이 바뀌는지 적습니다.

```md
| control | type/range | on-screen effect |
| --- | --- | --- |
| batch | range 1-8 | 블록 줄 수와 처리량 막대가 함께 바뀜 |
```

## 값이 정해지는 순서

1. 기본값(`value`)
2. 시각 `t`에서 계산한 drive 트랙. 타임라인이 값을 직접 움직여야 하면 `batch.drive(1, 8, {at, dur, ease})`를 씁니다.
3. 사용자 값. URL `?c.<name>=<v>`, `s.setControls`, `set(v)`, 독 조작으로 들어오고, 뒤에 온 것이 앞의 것을 덮습니다.

스톱이 바뀌면 사용자 값은 지워집니다. 그러면 값은 새 시각 `t`의 drive 값으로 돌아가고, drive가 없으면 기본값으로 돌아갑니다. `sticky: true`인 컨트롤만 사용자 값이 스톱을 옮겨도 남습니다.

## layout: 다시 재야 할 때

보통 값이 바뀌면 런타임은 `tl.seek(tl.t)`로 화면을 다시 그립니다. 값에 따라 요소 크기나 위치를 다시 재야 한다면(예: 줄 수가 바뀌어 연결선 좌표가 달라짐) `layout: true`를 줍니다. 그러면 값이 바뀔 때 seek 대신 `layout()`이 다시 측정합니다. 측정에 의존하는 값은 `s.onLayout(fn)` 안에서 계산합니다.
