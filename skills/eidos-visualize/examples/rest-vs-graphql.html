대가 · trade-off

모양의 자유에는 값이 붙는다

HTTP 캐시는 GET URL 단위로 동작한다. 모든 쿼리를 POST /graphql 하나로 보내면 CDN과 브라우저 캐시를 그냥 지나친다 (GET persisted query 같은 우회가 따로 필요)

모양의 자유는 서버의 복잡도로 치른다

  • 스키마·리졸버 설계필드마다 어디서 어떻게 가져올지 서버가 정의한다
  • N+1 문제댓글 3개의 작성자 → 조회 3번. DataLoader로 묶어야 한다
  • 쿼리 비용 제한깊이·복잡도 제한과 rate limit이 서버 몫이 된다
결론

화면이 다양하고 왕복이 비싸면 GraphQL

캐시와 단순함이 중요하면 REST

둘 다 HTTP 위의 선택지라 섞어 써도 된다 — 공개 목록·상세처럼 캐시가 잘 먹는 곳은 REST(GET), 화면마다 모양이 다른 앱 데이터는 GraphQL
