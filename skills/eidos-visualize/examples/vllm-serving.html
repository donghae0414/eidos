활성(배치 안) 대기 빈 슬롯
활성 32 · 대기 32 · 슬롯 32

단순 모델 (개념도 · 실측 아님)
active = min(동시 사용자, max_num_seqs)          배치에 실제로 들어가는 요청 수
iter   = 1 + active / 32                         배치가 클수록 한 iteration이 조금 느려짐
tok/s  ∝ active / iter                           → 배치를 키우면 오르다 포화
대기   = max(0, 동시 사용자 − max_num_seqs)       슬롯을 못 받은 사용자
E2E    ∝ (1 + 대기 / max_num_seqs) × iter         → 대기가 생기면 급증

처리량과 E2E는 서로 당깁니다 — 배치를 키우면 tok/s가 오르고, 사용자가 슬롯보다 많아지면 E2E가 뜁니다.

용어 한 줄 정리

묻던 단어가 그림의 어느 부분인지

  • iteration — 모델 forward 한 번. 활성 요청 모두가 토큰 하나씩 전진. batch size는 그 안의 요청 수, 상한이 max_num_seqs
  • prefill = context 단계(프롬프트 토큰 처리) → TTFT · decode = generation 단계(토큰 하나씩) → ITL · 합쳐서 E2E (vLLM 지표 이름은 prompt_tokens / generation_tokens)
  • max_num_batched_tokens — iteration의 토큰 예산. decode 먼저, 남는 칸에 prefill(잘라서 = chunked prefill), 긴 프롬프트는 long_prefill_token_threshold로 한 번 몫을 더 줄임
  • KV cache — 토큰마다 블록에 남는 K/V. 가득 차면 대기·preempt → 동시성의 진짜 상한
  • 동시 사용자 ↑ → tok/s는 포화, E2E는 대기열만큼 ↑ → max_num_seqs · 토큰 예산 · KV 메모리로 조절

처리량은 배치가, 응답 시간은 대기열이 정합니다. 그 사이에서 max_num_seqs와 토큰 예산을 고릅니다.
