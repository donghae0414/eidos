| flow.5 code 전달 | `code` 칩 | 인증 서버에서 나타나 리다이렉트 화살표를 타고 서비스에 도착 | 브라우저를 지나는 값은 몇 분짜리 일회용 code뿐이다 |
| flow.6 code 교환 | `code` 칩, `secret` 칩 | code가 서비스 생명선을 타고 내려오고 secret이 그 옆에 나타나 둘이 함께 인증 서버로 이동 | 교환은 서버끼리 하며 secret은 우리 서버에서만 출발한다 |
| flow.7 멈춤 | 프리즈 배지, 주석 카드 2장, 흐려진 헤더 | 화면이 한 번 번쩍이고 멈추며 교환 화살표 아래로 지시선과 주석이 붙음 | 이 순간 브라우저 열은 비어 있다. code는 한 번 쓰이고 secret은 서버 안에만 있다 |
| inside.1 code 조회 | 토큰 요청 카드, 장부의 code 행 | 요청 카드가 왼쪽에서 들어오고 장부에서 같은 code 행이 형광펜으로 칠해지며 첫 체크가 그려짐 | 서버는 받은 값을 믿지 않고 자기 장부에서 찾는다 |
| inside.2 발급 조건 검사 | 체크 표시 3개 | client_id, redirect_uri, client_secret 줄에 체크가 하나씩 그려짐 | code는 발급받은 그 서비스가 같은 조건으로 가져와야만 쓸 수 있다 |
| inside.3 code 소모, token 발급 | 장부 행 취소선, 상태 글자, token 카드 | 취소선이 행을 가로질러 그려지고 상태가 "사용됨"으로 바뀌며 token 카드가 튀어나옴 | code는 교환권이라 한 번 쓰면 없어지고, 진짜 열쇠는 이때 처음 만들어진다 |
| inside.4 재사용 거절 | 두 번째 요청 카드, ✗ 표시 | 같은 code를 든 카드가 다시 들어오고 그 위에 ✗가 그려지며 "이미 사용됨" 꼬리표가 붙음 | 같은 code로 두 번은 못 쓴다. 훔친 code는 늦으면 쓸모없다 |
| exchange.1 access token | 아래 생명선, `token` 칩 | 아래 절반의 생명선이 켜지고 token 칩이 인증 서버에서 튀어나와 서비스로 이동. code·secret 칩은 사라져 있음 | 토큰은 브라우저를 거치지 않고 서버로 온다. code와 secret은 이미 소모됐다 |
| exchange.2 API 호출 | `token` 칩 | 서비스 생명선을 타고 내려와 리소스 서버로 이동 | 토큰이 API를 여는 열쇠다 |
| exchange.3 프로필 | `프로필` 칩 | 리소스 서버에서 나타나 서비스로 돌아옴 | 서비스가 받는 것은 이름과 이메일이고 이것으로 로그인이 끝난다 |
| threat.1 secret 없음 | `secret` 칩, 점선 슬롯 | 앱 상자 안의 secret 칩이 아래로 떨어져 사라지고 슬롯에 "숨길 곳 없음"이 남음 | 기기에 배포되는 코드는 비밀을 지킬 수 없다 |
| threat.2 code 가로채기 | `code` 칩 2개 | 서버에서 앱으로 가던 code가 중간에서 둘로 갈라지고 하나는 공격자에게 내려감 | 리다이렉트 구간은 기기 안에서 가로챌 수 있다 |
| threat.3 훔친 code 교환 | 공격자의 `code` 칩, `token` 칩 | 공격자의 code가 서버로 가고 서버 검사가 "code 일치"만 켜진 뒤 token이 공격자로 내려옴 | secret이 없으면 서버는 앱과 공격자를 구별할 근거가 없다 |
| pkce.1 verifier와 challenge | `verifier` 칩, `challenge` 칩 | 앱 안에 verifier가 생기고 그 해시인 challenge만 서버로 가서 장부 슬롯에 들어감 | 비밀은 앱 안에 남고 서버는 자물쇠(해시)만 받아 둔다 |
| pkce.2 code 가로채기 (여전히) | `code` 칩 2개 | 서버→앱 code가 다시 갈라져 공격자도 code를 얻음 | PKCE는 가로채기를 막는 것이 아니라 훔친 code를 쓸모없게 만든다 |
| pkce.3 앱의 교환 | `code`·`verifier` 칩, 체크, `token` 칩 | 앱의 두 칩이 서버로 가고 "SHA-256(verifier) = challenge" 줄에 체크가 그려진 뒤 token이 앱으로 돌아옴 | 열쇠는 자물쇠와 맞는 verifier를 가진 쪽에만 간다 |
| pkce.4 공격자의 교환 | 공격자의 `code` 칩, ✗ 표시 | code만 서버로 가고 ✗가 그려지며 칩이 튕겨 돌아옴 | code만으로는 토큰을 얻을 수 없다 |
| summary.1~4 안전한 이유 | 카드 4장 | 제목이 가림막 뒤에서 올라온 뒤 카드가 한 장씩 올라오고 앞 카드는 옅어짐 | 지금 읽을 이유 하나만 또렷하다 |
| summary.5 핵심 문장 | 결론 첫 줄의 단어들 | 단어가 차례로 미끄러져 들어오고 "믿지 않는 것"이 크게 내리꽂힘. 네 카드는 다시 또렷해짐 | 강세는 "믿지 않는다"에 있다 |
| summary.6 마무리 | 결론 둘째 줄, 동그라미 | 둘째 줄이 올라오고 "진짜 열쇠는 서버 사이로만"에 손으로 그린 동그라미가 그려짐 | 결론을 손으로 짚는다 |
