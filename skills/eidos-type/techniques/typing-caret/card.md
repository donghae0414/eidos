# 타이핑 커서 (Typing Caret)

**장면 관계:** 한 장면 안에서 사람이 입력창에 글을 쳐 넣는 순간을 보여 줄 때 씁니다. 장면 경계의 `via` 값이 아니므로 `s.fx`로 부릅니다.

## 전달하는 의미
**이 글은 사람이 지금 치고 있다.** 글자가 불규칙한 박자로 하나씩 들어오고 커서가 마지막 글자 뒤를 따라가면, 화면의 글이 결과물이 아니라 입력 중인 요청이라는 뜻이 됩니다. 채팅 입력창의 프롬프트, 검색창의 검색어, 터미널의 명령처럼 "사람이 넣는 쪽"을 보여 주는 자리에 맞습니다. 글자는 바뀌거나 뒤섞이지 않고 원문 그대로 하나씩 쌓입니다.

## 언제 쓰나
- LLM 채팅 입력창에 프롬프트를 쳐 넣고 보내는 장면 (입력창 + 커서 + 전송 박자)
- 검색어, 명령, 폼 값처럼 사람이 입력하는 쪽과 시스템이 내놓는 쪽을 나눠 보여 줄 때
- 같은 입력창에 짧은 질문과 긴 질문을 차례로 쳐서 프롬프트의 차이가 보여야 할 때

## 피할 때
- 해시, 토큰, ID처럼 계산되어 나오는 값. 그쪽은 text-scramble입니다
- 입력창 없이 코드나 명령 한 줄이 생성되는 느낌만 필요할 때. text-scramble `mode: "type"`이 더 가볍습니다
- 문단 길이의 글. 커서를 따라 읽게 되어 느립니다. 두세 줄 안의 요청문에만 쓰세요
- 한 장면에 입력창 두 개. 커서가 둘이면 어디가 입력 중인지 모릅니다

## 사용법
```html
<div class="field"><p id="prompt">getUsers()가 요청마다 테이블 전체를 읽어. N+1 쿼리인지 보고 인덱스로 고쳐 줘.</p></div>
<p class="msg" id="sent">getUsers()가 요청마다 테이블 전체를 읽어. N+1 쿼리인지 보고 인덱스로 고쳐 줘.</p>
```
```js
s.tl.stop("빈 입력창");                                                   // 커서만 켜져 있음
const r = s.fx("typing-caret", { targets: "#prompt" });                   // 요소의 글자를 하나씩 침
s.tl.stop("프롬프트를 다 쳤다");                                          // 커서는 마지막 글자 뒤에 고정
s.tl.tween("#prompt", { opacity: [1, 0] }, { dur: 0.2 });                 // 전송 박자: 입력창 비우기
s.tl.tween("#sent", { opacity: [0, 1], y: [10, 0] }, { at: "<+=0.1", dur: 0.4, ease: "out" });
```
**글자 나누기.** 기법이 요소의 글자(마크업은 버리고 글자만, 연속 공백은 하나로)를 `Intl.Segmenter`의 grapheme 단위로 나눠 글자마다 `span.eidos-glyph`로 감싸고, 띄어쓰기 단위(어절)마다 `span.eidos-word`(inline-block, 줄바꿈 금지)로 묶습니다. 한글 음절, 이모지, 결합 문자는 한 단위로 들어옵니다. 아직 치지 않은 글자는 투명하게 자리를 차지하므로 줄바꿈이 처음부터 최종 상태와 같고, 커서가 줄 끝에 닿아도 주변 레이아웃이 흔들리지 않습니다. 띄어쓰기 없는 긴 영문이나 URL은 한 어절이 되어 줄을 넘칠 수 있으니 짧게 끊으세요.

**박자.** 첫 글자는 시작 시각에서 한 글자 간격이 지난 뒤 들어옵니다. 글자 간격은 평균 `1/cps`초이고, 글자마다 `Eidos.rng(seed)`로 뽑은 값으로 `±jitter` 비율만큼 흔들립니다. 띄어쓰기는 1.6배 길어서 단어 사이에 숨이 들어갑니다. 마지막 글자 뒤에는 `1/cps`초를 더 두고 끝납니다. 같은 seed면 언제나 같은 박자이므로 앞뒤로 넘기거나 `?t=`로 바로 열어도 같은 화면입니다.

**커서.** `span.eidos-caret`(currentColor 세로선)가 마지막으로 친 글자 뒤에 붙고, 띄어쓰기를 친 뒤에는 다음 어절 앞에서 기다립니다. 준비 깜빡임 없이 처음부터 끝까지 켜져 있습니다. 기존 stop과 겹치는 `at`도 지원하며, 각 stop에서는 글자와 커서 위치가 움직이지 않습니다. 색은 CSS로 바꿉니다(`.eidos-caret { border-color: var(--eidos-accent) }`).

## 파라미터
| 이름 | 기본값 | 설명 |
|---|---|---|
| `targets` | (필수) | 글을 쳐 넣을 요소들. 여러 개면 앞 요소를 다 친 뒤 다음 요소로 이어집니다 |
| `cps` | `18` | 초당 글자 수(공백 포함). 짧은 질문은 그대로, 긴 프롬프트는 `22`~`28`로 올리세요 |
| `jitter` | `0.4` | 간격의 불규칙 정도 0~1. `0`이면 기계처럼 일정, `1`이면 0~2배 사이로 흔들림 |
| `seed` | `1` | 간격 난수의 시드. 바꾸면 다른 박자가 나옵니다 |
| `caret` | `true` | 커서 표시. `false`면 같은 박자로 글자만 들어옵니다 |
| `at` | 이어서 | 시작 시각 |

반환값: `{ start, end, items: [{ el, start, end, text, caret }] }`. `caret`은 커서 요소(`caret: false`면 `null`)라서 입력창이 초점을 잃는 장면에서는 `s.tl.tween(r.items[0].caret, { opacity: [1, 0] }, { dur: 0 })`처럼 직접 끌 수 있습니다.

## 변형
- **전송 박자:** 다 친 stop 다음에 요소를 `opacity` 0으로 보내고 같은 글을 말풍선으로 띄우면 "보냈다"가 됩니다. 버튼은 `scale`을 한 번 눌렀다 놓는 트윈이면 충분합니다
- **짧은 질문 vs 긴 질문:** 같은 입력창에 요소 두 개를 겹쳐 두고(`grid-area: 1 / 1`) 차례로 치면 프롬프트 길이의 차이가 그대로 보입니다. 뒤 요소는 자기 차례 전까지 `opacity` 0으로 둡니다
- **기계 입력:** `jitter: 0`이면 봇이 넣는 값처럼 일정하게 들어옵니다
- **커서 없이:** `caret: false`는 자막처럼 글자만 쌓이는 변형입니다

## reduced-motion
첫 글자 간격이 지나면 글이 통째로 나타납니다. 커서는 글이 나타나기 전에는 첫 글자 앞에서 기다리다가, 글이 나타날 때 마지막 글자 뒤로 한 번에 옮겨 갑니다. stop에서는 글자와 커서 위치가 움직이지 않습니다. 글은 불투명도로만 나타나며, 커서 이동에는 트윈을 쓰지 않고 블러와 3D도 쓰지 않습니다.

## 같이 쓰기 좋은 기법
sequence-message(보낸 요청이 어디로 가는지), highlight-sweep(친 프롬프트 속 핵심 구절 짚기), stagger-reveal(답변 말풍선을 차례로 띄울 때), text-scramble(사람의 입력이 아니라 계산된 값일 때는 그쪽)
