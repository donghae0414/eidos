# 아이리스 (Iris)

## 전달하는 의미
**바로 이것에서 다음 이야기가 열린다.** 원이 특정 요소에서 튀어나오듯 커지며 화면을 삼킵니다. 시선이 그 요소에 묶인 채로 다음 장면에 도착하므로 "이 칸을 열어 보면", "이 줄이 원인이다"처럼 출발점이 중요하다는 뜻을 전합니다.

**장면 관계:** 출발한 요소가 중요함. 스토리보드 경계 표에서 다음 장면이 앞 장면의 특정 요소에서 비롯될 때 `via: "iris"`를 씁니다.

## 언제 쓰나
- 대시보드의 빨간 칸, 다이어그램의 한 노드를 눌러 그 상세로 들어가는 흐름
- 로그 한 줄, 코드 한 줄에서 원인 설명으로 넘어갈 때 (`mode: "cover"`로 강조색 원을 한 번 덮기)
- 마지막 장면을 닫으며 한 요소로 시선을 모을 때

## 피할 때
- 출발 요소가 없거나 화면 가운데의 아무 곳일 때. 그때는 cross-dissolve가 정직합니다.
- 들어가는 장면이 출발 요소를 확대한 같은 그림일 때. 그때는 `camera`가 공간 관계를 더 정확히 보여줍니다.
- 한 작품에서 3번 이상. 튀는 원은 강한 전환이라 두 번까지만 씁니다.

## 사용법
```js
s.scene("map", { el: "#a" });
// ...
s.scene("log", { el: "#b", via: "iris", with: { origin: "#pay" }, reason: "출발한 요소가 중요함" });
s.scene("cause", { el: "#c", via: "iris", with: { origin: "#culprit", mode: "cover", color: "cat-4" } });
```
`origin` 요소의 중심과 화면 가장 먼 모서리까지의 반지름은 `stage.onLayout`에서 재므로 창 크기가 바뀌어도 원이 같은 자리에서 열립니다. `reveal`은 들어오는 장면에 `clip-path: circle()`을 걸고, `cover`는 world 바로 뒤에 단색 원 레이어를 하나 만들어 덮었다가 걷어 냅니다.

## 파라미터
| 이름 | 기본값 | 설명 |
|---|---|---|
| `origin` | 화면 가운데 | 원이 시작할 요소(선택자나 요소). 찾지 못하면 오류 |
| `mode` | `"reveal"` | `reveal`: 원 안에 다음 장면이 보임. `cover`: 단색 원이 덮은 뒤 다음 장면이 드러남 |
| `color` | `"accent"` | `cover`의 원 색. `--eidos-*` 토큰 이름(`accent`, `fg`, `cat-4` …) |
| `dur` | reveal `0.9`, cover `1.2` | 전환 시간(초) |
| `ease` | `"pop"` | 원 크기의 이징. 기본값은 끝에서 살짝 넘쳤다가 돌아오는 오버슈트 |
| `at` | 타임라인 끝 | 시작 시점 |

## 변형
- **reveal (아이리스 인):** 다음 장면이 원 안에서 자랍니다. 출발 요소와 다음 장면이 직접 이어질 때.
- **cover (원팝):** 단색 원이 화면을 삼킨 뒤 옅어지며 다음 장면을 보여줍니다. 한 박자 쉬는 느낌이 있어 원인 공개, 장 전환 직전에 어울립니다.
- **오류 장면의 색:** 빨간 요소에서 cover를 쓸 때는 강조색 대신 `color: "cat-4"`(파랑)처럼 danger와 겹치지 않는 색을 고릅니다.

## reduced-motion
원이 자라지 않고 두 장면을 교차 페이드합니다. 오버슈트도 없습니다. 스톱 사이 이동은 즉시 처리되고 화면 전체가 200ms 동안 옅게 페이드됩니다.

## 같이 쓰기 좋은 기법
highlight-sweep(출발 요소를 먼저 짚고 아이리스로 들어가기), zoom-in(같은 그림을 확대만 할 때의 대안), dip-to-color(장이 바뀔 때)
