GET /orders · 로컬

로컬에서는 주문 목록 API가 충분히 빨랐다

12ms주문 20건, 개발 DB
SELECT * FROM orders LIMIT 20;
-- 화면에 고객 이름을 붙이려고 주문마다 한 번씩
SELECT name FROM users WHERE id = ?;   × 20
  • 테스트도 통과했다
  • 리뷰에서도 아무도 몰랐다
GET /orders · 프로덕션

프로덕션에서는 같은 코드가 4.8초 걸렸다

4,812ms주문 1,000건, 실제 DB
SELECT * FROM orders LIMIT 1000;
SELECT name FROM users WHERE id = ?;   × 1,000  ← N+1 쿼리
  • 쿼리 하나는 4ms지만 1,001번 왕복한다
  • 데이터가 늘면 그대로 비례해서 느려진다
GET /orders · 고친 뒤

JOIN 한 번으로 바꾸자 왕복이 하나로 줄었다

38ms주문 1,000건, 쿼리 1번
SELECT o.*, u.name
FROM orders o JOIN users u ON u.id = o.user_id
LIMIT 1000;
  • ORM에서는 fetch join이나 eager loading
  • 개발 DB에도 실제 규모의 데이터를 넣어 둔다
