Cache-aside: 앱이 DB에 쓰고 캐시는 지운다

쓰기는 DB로 바로 가고, 캐시 항목은 무효화만 합니다. 다음 읽기에서 캐시가 다시 채워집니다.

앱 서버
UPDATE users …1. DB에 쓰기
DB
원본 데이터
캐시
DEL user:422. 키 삭제
  • 구현이 가장 단순하다
  • 쓰기 직후 첫 읽기는 캐시 미스
  • 삭제와 읽기가 겹치면 잠깐 옛 값이 보일 수 있다

Write-through: 캐시를 거쳐 DB까지 함께 쓴다

캐시가 쓰기를 받아 DB에 동기로 반영합니다. 응답은 둘 다 끝난 뒤에 나갑니다.

앱 서버
SET user:421. 캐시에 쓰기
캐시
user:42 = {…}2. 동기 반영
DB
원본 데이터
  • 캐시와 DB가 항상 같다
  • 쓰기 지연 = 캐시 + DB
  • 한 번도 안 읽힐 값도 캐시에 들어간다

Write-back: 캐시에만 쓰고 DB는 나중에 몰아서

캐시가 쓰기를 모아 두었다가 주기적으로 DB에 내려보냅니다.

앱 서버
SET user:421. 캐시에 쓰기
캐시
dirty 항목 128개2. 모아 두기
DB
flush every 5s3. 일괄 반영
  • 쓰기 응답이 가장 빠르다
  • 캐시 노드가 죽으면 아직 안 내려간 쓰기는 사라진다
  • DB 부하가 고르게 퍼진다
