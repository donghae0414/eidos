주문 서비스: 주문을 만들고 바로 응답한다

결제와 배송을 기다리지 않습니다. 주문을 저장한 뒤 이벤트만 남깁니다.

받는 이벤트
HTTP 요청 (사용자)
주문 서비스
POST /orders
내보내는 이벤트
OrderCreated
  • 응답 시간 = 주문 저장 시간
  • 결제가 느려도 주문 화면은 빠르다

결제 서비스: 같은 이벤트를 받아 돈을 처리한다

주문 서비스와 같은 층위의 이웃입니다. 이벤트 하나로만 연결됩니다.

받는 이벤트
OrderCreated
결제 서비스
PaymentWorker
내보내는 이벤트
PaymentApproved
  • 실패하면 PaymentFailed를 내보낸다
  • 재시도해도 한 번만 결제되게 멱등 키를 쓴다

배송 서비스: 결제가 끝난 주문만 출고한다

세 서비스는 서로를 호출하지 않고, 이벤트를 따라 옆으로 이어집니다.

받는 이벤트
PaymentApproved
배송 서비스
ShipmentWorker
내보내는 이벤트
ShipmentScheduled
  • 결제 서비스가 죽어도 배송 큐는 쌓여서 기다린다
  • 각 서비스는 따로 배포한다
